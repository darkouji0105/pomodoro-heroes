## 4. 未決7件の裁き（**2026-09-02**）

**コンセプト文書の「未決定・要検証事項」7件に対する決定。**
**推奨は設計役が出し、人間が「未決7件を裁く」を選んだうえでの決定。**

### 4-1. インベントリ初期枠数 → ⚠ **鞄は2本に分ける。ラン専用の鞄を新設し、初期枠 8**

**⚠ 一番大事な指摘：コンセプト文書のインベントリは「ランの中で持ち歩く鞄」であって、拠点の倉庫ではない。**
**拠点の倉庫を有限にすると育成が詰む。2本に分ける。**

| | 中身 | 上限 |
|---|---|---|
| **拠点の `INVENTORY`** | いま在るもの。装備の個体・装飾・消耗品 | **無限のまま。さわらない** |
| **ランの鞄**（新設） | ⚠ **そのランで手に入れたものだけ。⚠ 持ち込みは無い＝入るとき空** | **有限。初期 8** |

**⚠ 鞄は空で始まる**（決定7・§4-8）。**持ち込める消耗品は無い。**
**ポーションも拠点では買えないので**（§4-3）、**鞄に入るものは全部そのランで手に入れたもの。**
**→ 「鞄の中身」＝「そのランで手に入れたもの」＝「全ロストの対象」。3つが同じものを指す。**

**決定**：

- **鞄が持つのは `item_id` と個数だけ。** **個体（`instance_id`）にしない**
- **個体化は「持ち帰りが確定した瞬間」に `add_to_inventory()` へ流す1本で行う**
- **初期枠は 8**（ポーション2 ＋ 鍵1 ＋ 戦利品5 で「終盤に埋まる」形）。**ショップで拡張できる**

**⚠ なぜ鞄を個体にしないか（守らないと黙って壊れる）**：

> **CLAUDE.md 8番「装備の個体は `add_to_inventory()` だけが作る」。**
> **鞄を2本目の入口にすると、装備が個体にならずに静かに消える。**
> `grep -n "_create_equipment_instance" autoload/game_manager.gd` の呼び出し元が
> **1箇所であることを保つ。**

**⚠ 初期枠 8 は仮置き。** コンセプト文書自身が「テストプレイで実測」と書いている。
**`scenario` で詰めること**（§6）。

### 4-2. 脱出コスト → **無料。ただし「その場で降りる」は全ロストにする**

**決定**：

- ⚠ **撤退できるのは「ボスを倒した直後」だけ**（決定15・§5-0）。**脱出そのものは無料。**
  ⚠ **ただし理由は初稿から差し替えた**（下記）
- ⚠ **いまの `abandon_floor()` に相当する「その場で降りる」ボタンは残す。**
  **押すと戦利品を全部失う＝死亡と同じ扱い**

**⚠ ボタンを消さないこと。** 消すと詰んだ人が閉じ込められる。
Roguebook の知見（**「なぜ負けたか分からない」「不公平だと感じた」と離脱する**）は、
**閉じ込めに直撃する。逃げ道は要る。ただしタダにしない。**

#### 4-2-1. ⚠ 「無料でよい理由」を差し替えた（**決定12 が初稿の根拠を消した**）

**初稿の理由**：「**お預けポイントまで戻る距離がコストなので、追加で取ると二重取りになる**」。
**⚠ 引き返さないので（決定12）、戻る距離というものが存在しない。根拠ごと消えた。**

**差し替えた理由**：**撤退を選べるのはボスを倒した先で、そこで
「持ち帰る／もう1枚潜る」を選ぶ**（決定15・§5-0）。**⚠ 持ち帰るほうを選んだ時点で、
その先のフロアで得られたはずの戦利品を全部捨てている。それがコスト。**

**→ 一貫原則の表の「深く潜る｜より良い戦利品｜撤退できる安全マージン」が、そのままこれ**（§2）。
**⚠ 脱出は原則の外にある行為ではなく、原則の表の1行そのものだった。**

### 4-3. ポーションの供給 → ⚠ **まず2件を新設する。ダンジョン内でしか手に入らない**

⚠ **コンセプトの中心にある「ポーション」が、実コードに1つも無い**（§3）。
⚠ **「MAX HP を回復できるのはポーションのみ」なので、無いまま入れると MAX HP が一方通行で削れて必ず詰む。**

**決定**：

| | 効くもの | 入手 |
|---|---|---|
| **HP回復のポーション**（新設） | いまの HP | **ダンジョン内だけ**（ランの一時通貨のショップ ＋ 宝箱） |
| **MAX HP回復のポーション**（新設） | **目減りした「ランの MAX HP」**（§4-4） | **同上。ただしHP回復より明確に希少にする** |
| **蘇生用ポーション**（新設・**決定10**） | **脱落したキャラを戻す**（§4-9） | **同上。⚠ 3種のうち一番希少にする** |

- ⚠ **コンセプト文書は「ポーション」を1語で書いているが、効くものが3つに分かれたので分ける**
- ⚠ **拠点では買えない。** **ゴールドで安全が無限に買えると、一貫原則がその1点で崩れる**
- ⚠ **セーフティネット：ボス後のショップに必ず並べる**（決定15・§5-0）
  （**層4に `shop` を必ず1個置いたのと同じ手＝前例があるので新しい仕組みを増やさない**）

**⚠ 供給量は未定。** §6 に残す。

#### 4-3-1. ⚠ ランの中で使うアイテムは**専用の `item_type` に分ける**（**人間の決定17・2026-09-02**）

**ポーション3件・鍵・ラン限定の消耗品は、拠点の消耗品と同じ型に入れない。**

**⚠ これで3つのことが「構造で」決まる**（**条件分岐を書かずに済む**）：

| | どう効くか |
|---|---|
| **全ロストの範囲** | ⚠ **その型のものは鞄にしか入らない。⚠ 「装備を除外する分岐」を書く必要が無い**（§4-8 と同じ考え方） |
| **拠点で買えないこと** | ⚠ **拠点のショップが扱う型に入っていない。⚠ 値段を付け忘れる事故が起きない**（§4-3） |
| **鞄・ショップ・宝箱の引き方** | ⚠ **3箇所とも「その型のものだけ」で引ける。⚠ ID の綴りで見分けない**（`ITEM_MASTER_PART_KIND` のコメントと同じ理由） |

**⚠ 型の名前は `GameStateKeys` に定数として置く**（`ITEM_TYPE_KEY_ITEM` と同じ並び。AGENTS.md「状態アクセスのルール」）。
**⚠ 文字列リテラルで書かないこと。**

**⚠ 逆向きの禁止**：**拠点の装備・装飾・ルーンを、この型に入れ替えないこと。**
**入れた瞬間に全ロストの対象になる**（§4-8 の決定が黙って崩れる）。

### 4-4. MAX HP → ⚠ **「素の MAX HP」と「ランの MAX HP」は別のもの**（**人間の決定8・2026-09-02**）

⚠ **これが難ダンジョンの HP 設計の土台。ここを混ぜると全部おかしくなる。**

| | 何か | どこが持つか | 削れるか |
|---|---|---|---|
| **素の MAX HP** | **育成の値。レベル・装備・研究から毎回引き直す** | **`CHARACTER_GROWTH`（拠点）** | ⚠ **絶対に削れない。ダンジョンは一切さわらない** |
| **ランの MAX HP** | ⚠ **そのランの中だけの上限。戦闘終了時の HP がそのまま次のランの MAX HP になる** | ⚠ **ランの状態（新設）。`{character_id: int}`** | ⚠ **削れる。⚠ ランを出ると捨てる** |

**決定**：

- ⚠ **ランに入った瞬間、素の MAX HP からランの MAX HP へ写す**（**数値1つ。マスターデータを複製しない＝CLAUDE.md 4番**）
- ⚠ **ランを出たら捨てる。次に入るときは素の MAX HP から満タンで始まる**（**人間の決定9＝案A・§6 の旧未決10**）
- **「終盤ほど削れにくくする」緩やかな減衰は入れない**（「終盤ほど安全がタダになる」は §2 に反する）
- ⚠ **下限は設けない**（**コンセプト文書の字面どおり。⚠ 下記のとおり前の決定を覆した**）

**⚠ 器の形は既に実績がある**：`FLOOR_RUN` の `hp_carry`（`{character_id: int}`・降りると丸ごと捨てる）が
**まさにこの形**（`scripts/utils/state_keys.gd:323`）。**ただしキーは借りない**（§7）。**形だけ借りる。**

#### 4-4-1. ⚠ 下限20% を撤回した（**設計役の前の推奨を、決定8・9 が崩した**）

**2026-09-02 の前半に「下限を初期 MAX HP の 20% に置く」と書いた。⚠ その根拠はもう成り立たない。**

- **前の根拠**：「MAX HP が 0 になったキャラは**復帰不能**で、それは緊張感ではなく詰み」
- ⚠ **崩れた理由**：**削れるのは「ランの MAX HP」だけで、ランを出れば元に戻る**（決定8・9）。
  **復帰不能はランの中で閉じる。恒久的な詰みはどこにも無い**

**→ 下限は要らない。コンセプト文書の「下限は設けない」に戻した。**

#### 4-4-2. ⚠ 「死亡」の定義（**初稿を訂正した。2026-09-02**）

**ランの MAX HP が 0 になったキャラは、そのランのあいだ脱落する。**
**編成3人が全員脱落＝死亡＝鞄を失う**（§4-8）。

**⚠ 初稿では「HP が 0 になった瞬間ではなく、ランの MAX HP が尽きた瞬間」と書いた。⚠ これは誤り。**

**既存仕様（`GAME_DESIGN.md:134`「死亡した味方は復活しない」）と突き合わせると、この2つは同じ瞬間になる**：

> **HP 0 → 死亡 → そのステージ中は復活しない → 戦闘終了時の HP は 0
> → ランの MAX HP が 0 → 脱落。⚠ 一本道で、分ける余地が無い。**

**→ 蘇生手段が無いと「1回死んだら、そのランのあいだずっと欠けたまま」になる。**
**⚠ 3人編成なので「1人死ぬ → 弱者狙いAI（§4-5）で2人目が死ぬ → 崩れる」が既定路線になる。**
**だから §4-9 が要る。**

### 4-5. 弱者狙いAI → **ボスと一部の敵だけ。⚠ 対策手段（かばう・ヘイト操作）は作らない**

**決定**：

- **出現はボスと一部の敵に限る。常時にしない**（**乱用すると負のスパイラルで詰む＝文書の指摘どおり**）
- **足すのは敵スキルの JSON だけ**（`target.sort: "lowest_hp"`。**語彙は既にある＝§3**）
- **予兆表示は入れる**（文書が要求している）
- ⚠ **かばう・ヘイト操作は作らない**

**⚠ 対策手段を作らない理由**：「かばう」はヘイトの器を要求し、**規模が跳ねる**。
代わりに**予兆表示 ＋ ポーション（§4-3）**で、「見えているのに手が無い」ではなく
**「見えているから先に手当てする」**にする。**§4-3 と §4-5 はここでつながっている。**

**⚠ 代償**：文書の注意点「**弱ってるキャラを見捨てる戦略が最適解になりうる**」を、
**意図どおりのものとして採ることになる。**

### 4-6. 回復スキルの使用回数制限 → **入れない。`cooldown_sec` で絞る**

**決定：「1戦闘あたり N 回」は入れない。**

**⚠ 理由**：器が2本になる。**「戦闘をまたいでリセットする責任者」が新しく要る。**
**`cooldown_sec` は既に必須項目として在り（§3）、同じ効果が出せる。**

文書の狙い（「これさえあれば無敵にならない」）は、
**回復量を割合で設計する**（文書が既に決めている）＋ `cooldown_sec` で足りる。

### 4-7. 危険度の事前開示 → **ノード種まで見せる。敵と戦利品の中身は見せない**

**決定**：

- **見せるのは「そこに何が在るか（ノード種）」まで**
- **敵の編成・戦利品の中身は見せない**
- **見える範囲はたいまつで買う**（**平面グリッドなので「何層先」ではなく「半径」**）

**⚠ ここは予告されていた。** `PLAN_SCENARIO_MAP.md:187` に、人間が了承済みの設計役の指摘が残っている：

> **「層構造ではたいまつの価値が平面マップより弱い。「負けてもノーリスク」の場所で
> 高い買い物をする理由が出にくいため。たいまつを主役にするなら、それは難ダンジョン側の看板になる」**

**⚠ 決定12（層構造）で、この指摘が半分だけ戻ってきた。⚠ ただし答えは出ている。**

**⚠ 指摘の理由は「層構造だから」ではなく「負けてもノーリスクだから」だった。**
**全ロストになった時点で、高い買い物をする理由は立つ。⚠ 層構造でも同じ。**

**⚠ 変わったのは「何の材料か」だけ**：

| | 旧（平面を採ると思っていたとき） | ⚠ **正（層構造・決定12）** |
|---|---|---|
| たいまつが買うもの | 引き返す判断の材料 | ⚠ **どの分岐へ進むかの材料** |

**⚠ ただし §5-2 の塞ぎ（宝箱をノード種に紐づける）を入れないと、⚠ ここも効かない。**
**どの分岐を選んでも報酬が同じなら、先が見えても買う理由が無い**
（**`FLOOR_GAMEPLAY_CURRENT.md` §2-D が実測でそう言っている**）。
**たいまつはこちらの看板。§2 の表に足したのはこのため。**

### 4-8. ⚠ 全ロストの範囲 → **ダンジョン内で手に入れたものだけ。装備は含まない**（**人間の決定7・2026-09-02**）

**コンセプト文書は「死亡ペナルティ：アイテム全ロスト」としか書いていない。**
**「アイテム」が何を指すのかを、ここで確定した。**

| | 失うか |
|---|---|
| **そのランで拾った戦利品・素材・ポーション・鍵** | ⚠ **失う** |
| **ランの一時通貨** | ⚠ **失う**（ランが終われば消えるもの） |
| **装備・装飾・ルーン（拠点から持ち込んだもの）** | ✅ **失わない** |
| **レベル・研究・拠点の倉庫** | ✅ **失わない** |

**⚠ 実装としては「鞄が消える」の一言で済む**（§4-1）。
**鞄には持ち込みが入らないので、「鞄の中身」＝「ダンジョン内で手に入れたもの」が常に成り立つ。**
**⚠ 装備を全ロストの判定から除外する条件分岐を書かないこと。** 構造で外れている。

**⚠ この決定が持つ意味（実装の回で効く）**：

- ✅ **拠点の育成が無駄にならない。** 装備を失わないので、**負けた回も「装備は残った」と言える**
  （Roguebook の知見「不公平だと感じると離脱する」への効き目が一番大きいのはここ）
- ⚠ **代わりに、失うものが「鞄1つ」に縮んだ。** **深く潜るリスクが軽くなる**
- ⚠⚠ **決定9（案A＝ランを出れば MAX HP は戻る）と合わせると、ランを越えて残るペナルティは1つも無い。**
  **負けて失うのは「鞄の中身」と「そのランに使った時間」だけ**

⚠ **→ ラン外のコストは、まるごと「入口」が背負うことになった**（§6 の未決7）。
**通行証なのか・スタミナなのか・ポモドーロ何回ぶんなのかが、**
**「1回の失敗がどれだけ痛いか」をほぼ単独で決める。** ⚠ **未決7 の重みが上がった。**

### 4-9. ⚠ 蘇生 → **蘇生用ポーション ＋ 休憩場所の2本**（**人間の決定10・2026-09-02**）

**⚠ 蘇生は「戦闘の外」でだけ起きる。戦闘の中では誰も立ち上がらない。**

| | 手段 | コスト |
|---|---|---|
| **1** | **蘇生用ポーションを使う**（**専用のアイテム。新設**） | **ポーション1個＝鞄の枠と持ち帰り価値** |
| **2** | **休憩場所で戻る**（**その層の分岐の1つ**） | ⚠ **その層の戦闘・レリック・宝箱を諦める** |

**⚠ なぜこの形なら作れるか（一番大事なところ）**：

> **「戦闘の中で蘇生する」には「死者を対象に取る」器が要り、それは無い**
> （`PLAN_SKILL_TEMPLATE.md:918`「他人を蘇生 … まだ書けない」）。
> **⚠ しかし「戦闘の外でランの MAX HP を戻す」だけなら、その器は要らない。**
> **状態への操作であって、スキルの `target` を通らないため。**

**→ 既存の「死亡した味方は復活しない」を1文字も覆さない。あれは戦闘の中の話**（§7）。

**⚠ 代償（受け入れたもの）**：
**3人が同じ戦闘の中で全滅したら、蘇生する機会が来ないまま死亡＝鞄を失う。**
**「戦闘が終わるまで持ちこたえられるか」が勝負になる。**

**⚠ 一貫原則との関係**（§2）：

| 要素 | 得るもの | 犠牲にするもの |
|---|---|---|
| **蘇生用ポーションを使う** | **仲間が戻る** | **鞄の枠と持ち帰り価値** |
| **休憩場所を選ぶ** | **仲間が戻る・HPが戻る** | ⚠ **その層で得られたはずの戦利品** |

#### 4-9-1. ⚠ 休憩場所の位置づけを差し替えた（**決定12 が初稿の根拠を消した**）

**初稿の理由**：「**そこまで引き返す距離がコストなので、無料にしてよい**」。
**⚠ 引き返さないので（決定12）、この根拠は消えた。⚠ このままだと蘇生が完全に無料になり、
一貫原則（§2）に正面から反する。**

**差し替え：休憩場所は「その層の分岐の1つ」。** **選ぶと、同じ層の戦闘・レリック・宝箱を踏めない。**

- ⚠ **`floor_1..5` が既にこの形**（`rest` を踏むと `battle` を踏めない）。**Slay the Spire の休憩も同じ**
- ✅ **新しい仕組みを増やさずにコストが戻る**
- ⚠ **ただし §5-2 の塞ぎ（宝箱をノード種に紐づける）を入れて初めて効く。**
  **宝箱が「移動」に紐づいたままだと、休憩を選んでも宝箱の数が変わらない＝コストが半分になる**

#### 4-9-2. ⚠ 復帰したときの値 → **半分**（**人間の決定13・2026-09-02**）

| | 復帰したとき |
|---|---|
| **ランの MAX HP** | ⚠ **素の MAX HP の 50%** |
| **いまの HP** | ⚠ **そのランの MAX HP の 50%**（＝**素の MAX HP の 25%**） |

**⚠ 「素の」を基準にする理由**：**脱落したキャラのランの MAX HP は 0。⚠ 0 の半分は 0 になる。**
**基準に取れるのは素の MAX HP しかない**（§4-4）。

**⚠ 蘇生用ポーションと休憩場所で値は変えない。どちらも半分。**
**ポーションが買っているのは「休憩場所を待たずに済むこと」＝タイミング**（§4-9 の表）。

**⚠ 復帰直後は素の 25% しか無い。⚠ 弱者狙いAI（§4-5）に真っ先に狙われる位置。**
**「蘇生させたらすぐ手当てする」が要る形になっている。⚠ 意図どおりとして採る。**

**⚠ 半々の読み方が2通りあった。** 設計役は「**MAX HP が半分・HP はその半分**」と取った。
**もし「MAX HP も HP も素の半分（＝復帰時は満タン）」の意味だったら、ここを直すこと。**
**⚠ 器は同じ。数字を2つ書き換えるだけ**（`revive_hp_ratio` と同じ形＝`skill_schema.gd:125`）。

## 5. マップの形＝**層構造（Slay the Spire そのもの）**（人間の決定12）

**下から上へ、層ごとに分岐を選んで進む。合流あり。⚠ 引き返さない。**

**⚠ 平面グリッド（決定5）は同じ日に覆った。** `PLAN_SCENARIO_MAP.md` §12-1 が
**難ダンジョンのために取っておいた形だったが、使わなかった。**
**§12-1 が挙げていた3つの理由のうち、「引き返す距離」が成り立たないため**
（**残る「まだ見ぬ区画」「たいまつが切れる恐怖」は層構造でも成立する**）。

**⚠ 平面はまだ捨てなくてよい。** `PLAN_SCENARIO_MAP.md` §12-1 に退避されたまま残っている。

### 5-0. ⚠⚠ 1ランの形（**人間の決定15・2026-09-02。⚠ お預けポイントは無くした**）

**1ラン ＝ フロアを何枚も重ねたもの。⚠ 撤退できるのは「ボスを倒した直後」だけ。**

```
  ラン開始（鞄は空）
    ↓
  ┌── フロア1 ────────────────────────┐
  │  層1 → 層2 → … → 層N → ボス      │  ← 層構造・合流あり・引き返さない
  └───────────────┬───────────────────┘
                  ↓ ボスを倒した
            ⚠ ショップ（ランの一時通貨で買う）
                  ↓
        ⚠⚠ 「続行する／撤退する」を選ぶ
           ├─ 撤退 → 鞄の中身を持ち帰る。ラン終了
           └─ 続行 → フロア2 へ（⚠ ランの MAX HP と鞄はそのまま持ち越す）
```

**⚠ 「お預けポイント」という専用の場所は作らない。⚠ ボスの後がそれ。**
**⚠ コンセプト文書の「ショップ：フロア最後に配置」と同じ形**（`00_concept/game_design_doc.md`）。

**⚠ これで決まること**：

| | |
|---|---|
| **「深く潜る」の単位** | ⚠ **層ではなくフロア。⚠ 1枚多く潜るか、そこで降りるか** |
| **撤退できる回数** | ⚠ **フロアの数だけ。⚠ 途中では降りられない**（**「その場で降りる」は全ロスト＝§4-2**） |
| **ランの MAX HP と鞄** | ⚠ **フロアをまたいで持ち越す。⚠ ラン全体で1本**（§4-4・§4-1） |
| **1ランの長さ** | ⚠ **プレイヤーが決める。⚠ 固定ではない** |

**⚠ ショップは「見せる」ところまでが仕事。⚠ 買っても買わなくても、次に続行か撤退かを選ぶ。**

### 5-1. ⚠ 「引き返さない」が効く3箇所

**この1点が、一貫原則（§2）の3つの行の中身を決めている。**

| | どういうことになるか |
|---|---|
| **撤退（ボスの後）** | ⚠ **戻って脱出するのではない。⚠ ボスを倒した先に着いて、そこで「持ち帰る／もう1枚潜る」を選ぶ**（§4-2・§5-0） |
| **休憩場所** | ⚠ **その層の分岐の1つ。⚠ 選ぶと、その層の戦闘・レリック・宝箱を諦めることになる**（§4-9）。⚠ **撤退とは別物** |
| **たいまつ** | ⚠ **「引き返す判断」ではなく「どの分岐へ進むか」の材料**（§4-7） |

### 5-2. ⚠ 塞ぐ穴が入れ替わった（**平面の穴は消え、シナリオ側の穴が来た**）

**⚠ 平面の穴（「遠回りするほど宝箱が増える」＝§12-1 が特定していたもの）は、引き返さないので消えた。**
**⚠ 代わりに `floor_1..5` の穴がそのまま来る。**

> **⚠ 宝箱が「移動」に紐づくと、歩数はどのルートでも同じなので、
> どの分岐を選んでも報酬の総量が動かない**（`FLOOR_GAMEPLAY_CURRENT.md` §2-B・実測 1.99 個/周）。
> **→ 分岐が「戦うか休むか」だけの選択になり、たいまつを買う理由も薄くなる。**

**⚠ 塞ぎ方：宝箱を「移動」ではなく「ノード種」に紐づける。**
**戦闘ノードは多く落とす／休憩は落とさない。**

**⚠ これは `FLOOR_GAMEPLAY_CURRENT.md` §6 の論点1 の案B そのもの。**
**シナリオ側では保留になったが、⚠ 難ダンジョンでは最初からこの形で作る**
（**あとから直すと `economy` の数字が全部動くため**）。

**⚠ `floor_1..5` の器は借りない。** `_build_floor_map()` と `get_available_moves()` は
**シナリオ側の器で、仕様が別。⚠ 形は同じでも関数は分ける**（借りると両方の仕様が1本に同居する）。

## 7. 触ると黙って壊れるもの（**難ダンジョン側**）

- **`add_to_inventory()` を2本目にしない。** ランの鞄から拠点へ流す口も**そこを通す**（§4-1・CLAUDE.md 8番）
- **`_roll_weighted_table()` にボーナスを足さない。** 抽選の本体は1本だけ
- **`SKILL_SLOT_COUNT`（2）を `.tres` に出さない。** バランス数値ではなく構造（`game_manager.gd:3362` のコメント）
- **`skill_schema.gd` の `SORTS_KNOWN` に語を足さない。** `lowest_hp` は既に在る（§3）
- **`MasterDataLoader` が返す数値は必ず `int()` で包む**（CLAUDE.md 3番）
- **状態にマスターデータを複製しない**（CLAUDE.md 4番）。**鞄が持つのは `item_id` と個数だけ**
- **`FLOOR_RUN` を難ダンジョンに使い回さない。** シナリオ側の器。**別のキーを立てる**
- ⚠⚠ **「素の MAX HP」を書き換えない。** ダンジョンが触るのは**ランの MAX HP だけ**（§4-4）。
  **`CHARACTER_GROWTH` の `stats` はレベル由来の素の値だけを持つ**（CLAUDE.md 4番）。
  **ここを書き換えると、セーブに削れた値が焼き付いて二度と戻らない**
- ⚠ **「死亡した味方は復活しない」（`GAME_DESIGN.md:134` ほか2箇所）を覆さない。** **あれは戦闘の中の話。**
  **蘇生は戦闘の外でだけ起こす**（§4-9）。**戦闘の中で立ち上がらせようとすると「死者を対象に取る」器が要り、規模が跳ねる**
- ⚠ **`BUFF_ON_DEATH`（自己復活）の `unit.max_hp` は「ランの MAX HP」を指す。** **素の MAX HP を読ませない**
- ⚠ **蘇生用ポーションを「MAX HP 回復ポーション」と同じ品にしない。** **3種は別のもの**（§4-3）
- ⚠⚠ **拠点の装備・装飾・ルーンを、ラン専用の `item_type` に入れ替えない**（§4-3-1）。
  **入れた瞬間に全ロストの対象になる。⚠ 決定7（装備は失わない）が黙って崩れる**
- ⚠ **ラン専用の `item_type` を文字列リテラルで書かない。** `GameStateKeys` の定数を立てる
  （`ITEM_TYPE_KEY_ITEM` と同じ並び。AGENTS.md「状態アクセスのルール」）
- ⚠ **撤退できるのはボスの後だけ**（決定15）。**層の途中に降り口を足さない。**
  **足すと「潜るか降りるか」の決断が消え、一貫原則の柱が1本抜ける**
