## 4. 未決7件の裁き（**2026-09-02**）

**コンセプト文書の「未決定・要検証事項」7件に対する決定。**
**推奨は設計役が出し、人間が「未決7件を裁く」を選んだうえでの決定。**

### 4-1. インベントリ初期枠数 → ⚠ **鞄は2本に分ける。ラン専用の鞄を新設し、初期枠 8**

**⚠ 一番大事な指摘：コンセプト文書のインベントリは「ランの中で持ち歩く鞄」であって、拠点の倉庫ではない。**
**拠点の倉庫を有限にすると育成が詰む。2本に分ける。**

| | 中身 | 上限 |
|---|---|---|
| **拠点の `INVENTORY`** | いま在るもの。装備の個体・装飾・消耗品 | **無限のまま。さわらない** |
| **ランの鞄**（新設） | ⚠ **そのランで手に入れたものだけ。⚠ 持ち込みは無い＝入るとき空** | **有限。初期 8** |

**⚠ 鞄は空で始まる**（決定7・§4-8）。**持ち込める消耗品は無い。**
**ポーションも拠点では買えないので**（§4-3）、**鞄に入るものは全部そのランで手に入れたもの。**
**→ 「鞄の中身」＝「そのランで手に入れたもの」＝「全ロストの対象」。3つが同じものを指す。**

**決定**：

- **鞄が持つのは `item_id` と個数だけ。** **個体（`instance_id`）にしない**
- **個体化は「持ち帰りが確定した瞬間」に `add_to_inventory()` へ流す1本で行う**
- **初期枠は 8**（ポーション2 ＋ 鍵1 ＋ 戦利品5 で「終盤に埋まる」形）。**ショップで拡張できる**

**⚠ なぜ鞄を個体にしないか（守らないと黙って壊れる）**：

> **CLAUDE.md 8番「装備の個体は `add_to_inventory()` だけが作る」。**
> **鞄を2本目の入口にすると、装備が個体にならずに静かに消える。**
> `grep -n "_create_equipment_instance" autoload/game_manager.gd` の呼び出し元が
> **1箇所であることを保つ。**

**⚠ 初期枠 8 は仮置き。** コンセプト文書自身が「テストプレイで実測」と書いている。
**`scenario` で詰めること**（§6）。

### 4-2. 脱出コスト → **無料。ただし「その場で降りる」は全ロストにする**

**決定**：

- **お預けポイントからの脱出そのものは無料。** **戻る距離がコストなので、追加で取ると二重取りになる**
  （**一貫原則の表に「脱出」の行が無いのは、原則から出てこないことの表れ**）
- ⚠ **いまの `abandon_floor()` に相当する「その場で降りる」ボタンは残す。**
  **押すと戦利品を全部失う＝死亡と同じ扱い**

**⚠ ボタンを消さないこと。** 消すと詰んだ人が閉じ込められる。
Roguebook の知見（**「なぜ負けたか分からない」「不公平だと感じた」と離脱する**）は、
**閉じ込めに直撃する。逃げ道は要る。ただしタダにしない。**

### 4-3. ポーションの供給 → ⚠ **まず2件を新設する。ダンジョン内でしか手に入らない**

⚠ **コンセプトの中心にある「ポーション」が、実コードに1つも無い**（§3）。
⚠ **「MAX HP を回復できるのはポーションのみ」なので、無いまま入れると MAX HP が一方通行で削れて必ず詰む。**

**決定**：

| | 効くもの | 入手 |
|---|---|---|
| **HP回復のポーション**（新設） | いまの HP | **ダンジョン内だけ**（ランの一時通貨のショップ ＋ 宝箱） |
| **MAX HP回復のポーション**（新設） | 目減りした MAX HP | **同上。ただしHP回復より明確に希少にする** |

- ⚠ **コンセプト文書は両方を「ポーション」と呼んでいるが、効くものが違うので分ける**
- ⚠ **拠点では買えない。** **ゴールドで安全が無限に買えると、一貫原則がその1点で崩れる**
- **セーフティネット：お預けポイントに必ず1個置く**
  （**層4に `shop` を必ず1個置いたのと同じ手＝前例があるので新しい仕組みを増やさない**）

**⚠ 供給量は未定。** §6 に残す。

### 4-4. MAX HP → ⚠ **「素の MAX HP」と「ランの MAX HP」は別のもの**（**人間の決定8・2026-09-02**）

⚠ **これが難ダンジョンの HP 設計の土台。ここを混ぜると全部おかしくなる。**

| | 何か | どこが持つか | 削れるか |
|---|---|---|---|
| **素の MAX HP** | **育成の値。レベル・装備・研究から毎回引き直す** | **`CHARACTER_GROWTH`（拠点）** | ⚠ **絶対に削れない。ダンジョンは一切さわらない** |
| **ランの MAX HP** | ⚠ **そのランの中だけの上限。戦闘終了時の HP がそのまま次のランの MAX HP になる** | ⚠ **ランの状態（新設）。`{character_id: int}`** | ⚠ **削れる。⚠ ランを出ると捨てる** |

**決定**：

- ⚠ **ランに入った瞬間、素の MAX HP からランの MAX HP へ写す**（**数値1つ。マスターデータを複製しない＝CLAUDE.md 4番**）
- ⚠ **ランを出たら捨てる。次に入るときは素の MAX HP から満タンで始まる**（**人間の決定9＝案A・§6 の旧未決10**）
- **「終盤ほど削れにくくする」緩やかな減衰は入れない**（「終盤ほど安全がタダになる」は §2 に反する）
- ⚠ **下限は設けない**（**コンセプト文書の字面どおり。⚠ 下記のとおり前の決定を覆した**）

**⚠ 器の形は既に実績がある**：`FLOOR_RUN` の `hp_carry`（`{character_id: int}`・降りると丸ごと捨てる）が
**まさにこの形**（`scripts/utils/state_keys.gd:323`）。**ただしキーは借りない**（§7）。**形だけ借りる。**

#### 4-4-1. ⚠ 下限20% を撤回した（**設計役の前の推奨を、決定8・9 が崩した**）

**2026-09-02 の前半に「下限を初期 MAX HP の 20% に置く」と書いた。⚠ その根拠はもう成り立たない。**

- **前の根拠**：「MAX HP が 0 になったキャラは**復帰不能**で、それは緊張感ではなく詰み」
- ⚠ **崩れた理由**：**削れるのは「ランの MAX HP」だけで、ランを出れば元に戻る**（決定8・9）。
  **復帰不能はランの中で閉じる。恒久的な詰みはどこにも無い**

**→ 下限は要らない。コンセプト文書の「下限は設けない」に戻した。**

#### 4-4-2. ⚠ これで「死亡」の定義が決まる

**ランの MAX HP が 0 になったキャラは、そのランのあいだ脱落する。**
**編成3人が全員脱落＝死亡＝鞄を失う**（§4-8）。

⚠ **「死亡ペナルティ：アイテム全ロスト」の「死亡」が、ここで初めて具体的な条件になった。**
⚠ **HP が 0 になった瞬間ではなく、ランの MAX HP が尽きた瞬間。** 実装の回で取り違えないこと。

### 4-5. 弱者狙いAI → **ボスと一部の敵だけ。⚠ 対策手段（かばう・ヘイト操作）は作らない**

**決定**：

- **出現はボスと一部の敵に限る。常時にしない**（**乱用すると負のスパイラルで詰む＝文書の指摘どおり**）
- **足すのは敵スキルの JSON だけ**（`target.sort: "lowest_hp"`。**語彙は既にある＝§3**）
- **予兆表示は入れる**（文書が要求している）
- ⚠ **かばう・ヘイト操作は作らない**

**⚠ 対策手段を作らない理由**：「かばう」はヘイトの器を要求し、**規模が跳ねる**。
代わりに**予兆表示 ＋ ポーション（§4-3）**で、「見えているのに手が無い」ではなく
**「見えているから先に手当てする」**にする。**§4-3 と §4-5 はここでつながっている。**

**⚠ 代償**：文書の注意点「**弱ってるキャラを見捨てる戦略が最適解になりうる**」を、
**意図どおりのものとして採ることになる。**

### 4-6. 回復スキルの使用回数制限 → **入れない。`cooldown_sec` で絞る**

**決定：「1戦闘あたり N 回」は入れない。**

**⚠ 理由**：器が2本になる。**「戦闘をまたいでリセットする責任者」が新しく要る。**
**`cooldown_sec` は既に必須項目として在り（§3）、同じ効果が出せる。**

文書の狙い（「これさえあれば無敵にならない」）は、
**回復量を割合で設計する**（文書が既に決めている）＋ `cooldown_sec` で足りる。

### 4-7. 危険度の事前開示 → **ノード種まで見せる。敵と戦利品の中身は見せない**

**決定**：

- **見せるのは「そこに何が在るか（ノード種）」まで**
- **敵の編成・戦利品の中身は見せない**
- **見える範囲はたいまつで買う**（**平面グリッドなので「何層先」ではなく「半径」**）

**⚠ ここは予告されていた。** `PLAN_SCENARIO_MAP.md:187` に、人間が了承済みの設計役の指摘が残っている：

> **「層構造ではたいまつの価値が平面マップより弱い。「負けてもノーリスク」の場所で
> 高い買い物をする理由が出にくいため。たいまつを主役にするなら、それは難ダンジョン側の看板になる」**

**全ロストなら、たいまつは「引き返す判断の材料」になり、初めて高い買い物をする理由が立つ。**
**たいまつはこちらの看板。§2 の表に1行足したのはこのため。**

### 4-8. ⚠ 全ロストの範囲 → **ダンジョン内で手に入れたものだけ。装備は含まない**（**人間の決定7・2026-09-02**）

**コンセプト文書は「死亡ペナルティ：アイテム全ロスト」としか書いていない。**
**「アイテム」が何を指すのかを、ここで確定した。**

| | 失うか |
|---|---|
| **そのランで拾った戦利品・素材・ポーション・鍵** | ⚠ **失う** |
| **ランの一時通貨** | ⚠ **失う**（ランが終われば消えるもの） |
| **装備・装飾・ルーン（拠点から持ち込んだもの）** | ✅ **失わない** |
| **レベル・研究・拠点の倉庫** | ✅ **失わない** |

**⚠ 実装としては「鞄が消える」の一言で済む**（§4-1）。
**鞄には持ち込みが入らないので、「鞄の中身」＝「ダンジョン内で手に入れたもの」が常に成り立つ。**
**⚠ 装備を全ロストの判定から除外する条件分岐を書かないこと。** 構造で外れている。

**⚠ この決定が持つ意味（実装の回で効く）**：

- ✅ **拠点の育成が無駄にならない。** 装備を失わないので、**負けた回も「装備は残った」と言える**
  （Roguebook の知見「不公平だと感じると離脱する」への効き目が一番大きいのはここ）
- ⚠ **代わりに、失うものが「鞄1つ」に縮んだ。** **深く潜るリスクが軽くなる**
- ⚠⚠ **決定9（案A＝ランを出れば MAX HP は戻る）と合わせると、ランを越えて残るペナルティは1つも無い。**
  **負けて失うのは「鞄の中身」と「そのランに使った時間」だけ**

⚠ **→ ラン外のコストは、まるごと「入口」が背負うことになった**（§6 の未決7）。
**通行証なのか・スタミナなのか・ポモドーロ何回ぶんなのかが、**
**「1回の失敗がどれだけ痛いか」をほぼ単独で決める。** ⚠ **未決7 の重みが上がった。**

## 5. マップの形＝**平面グリッド**（人間の決定5）

**`PLAN_SCENARIO_MAP.md` §12-1 が難ダンジョンのために取っておいた形。予定どおり採用した。**

**採る理由（§12-1 が既に書いていたもの）**：

> **難ダンジョンの決定事項（撤退式・鞄が有限・全ロスト・深く潜るほど報酬）は、
> 「引き返す距離」「まだ見ぬ区画」「たいまつが切れる恐怖」が効く平面探索の文法とよく合う。**

**⚠ `floor_1..5` の層構造は流用できない。** `_build_floor_map()` と `get_available_moves()` は
**シナリオ側の器なので、そのまま借りない**（借りると両方の仕様が1本の関数に同居する）。

### 5-1. ⚠ 先に塞ぐ穴（**§12-1 が特定済み。設計役が再発見したのではない**）

> **平面だと宝箱が「移動」に紐づくので、遠回りするほど増える。**

## 7. 触ると黙って壊れるもの（**難ダンジョン側**）

- **`add_to_inventory()` を2本目にしない。** ランの鞄から拠点へ流す口も**そこを通す**（§4-1・CLAUDE.md 8番）
- **`_roll_weighted_table()` にボーナスを足さない。** 抽選の本体は1本だけ
- **`SKILL_SLOT_COUNT`（2）を `.tres` に出さない。** バランス数値ではなく構造（`game_manager.gd:3362` のコメント）
- **`skill_schema.gd` の `SORTS_KNOWN` に語を足さない。** `lowest_hp` は既に在る（§3）
- **`MasterDataLoader` が返す数値は必ず `int()` で包む**（CLAUDE.md 3番）
- **状態にマスターデータを複製しない**（CLAUDE.md 4番）。**鞄が持つのは `item_id` と個数だけ**
- **`FLOOR_RUN` を難ダンジョンに使い回さない。** シナリオ側の器。**別のキーを立てる**
- ⚠⚠ **「素の MAX HP」を書き換えない。** ダンジョンが触るのは**ランの MAX HP だけ**（§4-4）。
  **`CHARACTER_GROWTH` の `stats` はレベル由来の素の値だけを持つ**（CLAUDE.md 4番）。
  **ここを書き換えると、セーブに削れた値が焼き付いて二度と戻らない**
- ⚠ **「死亡」は HP が 0 になった瞬間ではない。ランの MAX HP が尽きた瞬間**（§4-4-2）
