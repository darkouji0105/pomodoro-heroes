## 3. フロアの形

### 3-1. 決まったこと

- ⚠ **フロアは5本**（決定6）
- ⚠ **1フロア＝分岐のあるマップ。⚠ ノードを1つずつ歩く**
- ⚠ **クリア条件はボス撃破**
- ⚠ **ボスの位置は固定で、⚠ 最初から見えている**（視界の外でも見える）
- ⚠ **負けてもノーリスク・何度でもやり直せる**
- ⚠ **マップ生成は「ノードの並び順を変えるだけ」。⚠ 各ノードの処理は共通のロジックを使い回す**

### 3-2. ⚠ 設計役が見つけた矛盾（**人間の確認待ち**）

⚠ **`DISCUSSION_scenario_map.md` は「2分岐でどんどん増える構造（合流なし）」と「ボスは固定位置・クリア条件はボス撃破」を同時に書いている。⚠ この2つは両立しない。**

⚠ **合流が無いと、n段のマップは葉が 2^(n-1) 個できる。⚠ ボスが固定位置なら、⚠ ボスに繋がる葉は1つだけ。⚠ 残りの葉は全部行き止まりになり、⚠ 「引き返せない一本道」の前提では詰む。**

| 案 | 中身 | 評価 |
|---|---|---|
| ⚠ **(a) 最終段だけ合流させる**（推奨） | ⚠ **途中の段は合流なしで増え、⚠ 最深段の葉が全部ボスへ入る。⚠ 「合流なし」は途中の段の話と解釈する** | ⚠ **どのルートを選んでも必ずボスに着く。⚠ ルート選択が「道中に何を踏むか」の選択になる。⚠ メモの「取りこぼしという概念がない」とも噛み合う** |
| ⚠ **(b) 葉＝ボス** | ⚠ **どの葉に着いてもボス戦。⚠ ボスは「位置」ではなく「深さ」** | ⚠ **「ボスの位置が見えている」の意味が薄れる** |
| ⚠ **(c) 行き止まりを認め、引き返せる** | ⚠ **一本道をやめる** | ⚠ **移動回数が読めなくなり、⚠ 宝箱の期待値（§4-3）が計算できない** |

⚠ **推奨は (a)。⚠ 人間が決めるまで、⚠ 段数もノード数も確定させない。**

### 3-3. ⚠ 段数（**未決・(a) を採る前提の推奨値**）

⚠ **合流なしで n 段のとき、⚠ 生成されるノードは 2^n − 1 個、⚠ 実際に歩くのは n マス。**

| 段数 | 生成されるノード | 歩くマス |
|---|---|---|
| 4 | 15 | 4 |
| ⚠ **5**（推奨） | ⚠ **31** | ⚠ **5** |
| 6 | 63 | 6 |
| 8 | 255 | 8 |

⚠ **推奨は5段。⚠ 理由：いまの1周が5ウェーブなので体感の長さを揃えられる。⚠ 31ノードなら画面に収まる。⚠ 8段（255ノード）は生成も描画も破綻する。**
⚠ **フロアごとに段数を変えるかは未決（§10）。**

### 3-4. ノード4種

| ノード | 中身 | ⚠ **周回時** |
|---|---|---|
| ⚠ **戦闘** | ⚠ **敵と戦う（基本のマス）。⚠ いまの `waves` 1本ぶんに相当** | ⚠ **結果のみ確定** |
| ⚠ **ショップ** | ⚠ **①入店時に無料ガチャ1回（恒久資産・持ち帰れる）②恒久通貨で消耗品（フロア内専用・持ち帰り不可）③たいまつ購入** | ⚠ **無料ガチャだけ自動処理。⚠ 購入は発生しない** |
| ⚠ **バフ選択** | ⚠ **2〜3択。⚠ フロア内限定の一時強化** | ⚠ **発生しない**（無意味なため） |
| ⚠ **休憩** | ⚠ **HP回復のみ**（まずはシンプルに） | ⚠ **発生しない** |

⚠ **休憩が意味を持つには HP をフロア内で持ち越す必要がある（§2 の最終行）。⚠ 新しい器。**

## 4. 宝箱の作り直し

### 4-1. ⚠ いまの宝箱（**実コード**）

- ⚠ **積む口は `grant_chest()` の1本。⚠ 戦闘（`_grant_stage_chest`）もポモドーロの加護（`claim_pending_chests`）もここを通る**
- ⚠ **`chests.json` は7件。⚠ `generic` / `bonus_small` / `bonus_medium` / `bonus_large`（固定報酬・⚠ 中身は4件とも `construction_material_1` だけ）＋ `stage_1..3`（抽選・⚠ 中身は装備のみ）**
- ⚠ **「3割の周でしか出ない」の正体は、⚠ 抽選表のハズレ枠 `{"item_id": "", "weight": 70}`。⚠ これを引くと `_is_rewards_empty()` が真になり、⚠ `grant_chest()` が `false` を返して宝箱そのものを積まない**（`game_manager.gd:930`）
- ⚠ **中身は積むときに振って個体に焼き込む。⚠ 開けるときには振らない**
- ⚠ **個体は `PENDING_CHESTS` に `{instance_id, chest_id, source, obtained_at, opened, rewards}` で溜まる**

### 4-2. 決まったこと

1. ⚠ **ハズレ枠（`weight: 70` の空欄）を廃止する。⚠ 宝箱が出ると決まったら必ず中身がある**
2. ⚠ **`chest_id` は「フロア × レアリティ」にする**。⚠ **`floor_1_common` / `floor_1_rare` / `floor_1_epic` / `floor_1_legendary` … の形**
3. ⚠ **5フロア × 4段階 ＝ 20件。⚠ 既存の `generic` / `bonus_*` の4件はそのまま残す**（⚠ **ポモドーロの加護が使っている**）
4. ⚠ **深度補正は「どの `chest_id` を積むか」を呼ぶ側で選ぶ**。⚠ **`_roll_weighted_table()` は触らない**
5. ⚠ **溜める方式は変えない**（`PENDING_CHESTS` を通す）。⚠ **副産物として宿題23（戦闘結果に宝箱が出ない）は「マップ上に出る」で解消する**
6. ⚠ **`name_key` はレアリティ側だけ持つ。⚠ フロアごとに名前を分けない**（⚠ **`ja.csv` は4行で済む**）

### 4-3. ⚠ ハズレ枠を廃止した帰結（**一番大きい**）

⚠ **いまは「7割の周で宝箱そのものが積まれない」ことが、⚠ 宝箱の量を絞る唯一の栓になっている。⚠ 廃止すると栓が消える。**

- ⚠ **新しい栓は「移動あたりの出現確率」**（メモの「移動に紐づく抽選」）
- ⚠ **1周あたりの宝箱数 ＝ 移動回数 × 出現確率。⚠ §3-3 の段数がそのまま効く**
- ⚠ **`_is_rewards_empty()` の枝は残す**（保険。⚠ ただし平常系では二度と通らなくなる）
- ⚠ **`scenario=economy` の「1周で入るもの」が全部動く。⚠ 数値を入れる段で必ず回し直す**

### 4-4. ⚠ 1フロア最低1回の保証

⚠ **メモの「クリアまでに一度も当たらなければ確定発生させる」。⚠ フロア内にカウンタが要る**（§7 の状態キー）。

### 4-5. ⚠ レアリティは開封前から見える

⚠ **色・エフェクトで示唆する。⚠ 隠さない。**
⚠ **「奥ほど良い物が出やすい」は隠しパラメータにせず、⚠ 画面かテキストで明示する**（メモの明文化要求）。

## 6. 周回（自動処理）

- ⚠ **初回（未踏破）… マップを実際に歩く**
- ⚠ **周回（踏破済み）… 内部で一括処理して結果だけ出す**
- ⚠ **周回で発生するもの … 戦闘結果・宝箱・ショップの無料ガチャ**
- ⚠ **周回で発生しないもの … バフ選択・休憩・消耗品購入・たいまつ**（⚠ **フロア内限定のものは全部**）

⚠ **これは宿題49 の復活（§1-1）。⚠ 新しい器が要る：「戦闘を回さずに結果だけ作る口」。⚠ いまは `battle_controller` が戦闘を回さないと `apply_battle_rewards()` に届かない。**
