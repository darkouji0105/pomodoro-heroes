## 3. フロアの形

### 3-1. 決まったこと

- ⚠ **フロアは5本**（決定6）
- ⚠ **1フロア＝分岐のあるマップ。⚠ ノードを1つずつ歩く**
- ⚠ **クリア条件はボス撃破**
- ⚠ **ボスの位置は固定で、⚠ 最初から見えている**（視界の外でも見える）
- ⚠ **負けてもノーリスク・何度でもやり直せる**
- ⚠ **マップ生成は「ノードの並び順を変えるだけ」。⚠ 各ノードの処理は共通のロジックを使い回す**

### 3-2. ⚠ マップの形＝**層構造（合流あり）**（**2026-08-25・人間が決定**）

```
        ◆ ボス（常に見えている）
       /|\
      ● ● ●      ← 4層
      |\|/|
      ● ● ●      ← 3層
      |/|\|
      ● ● ●      ← 2層
       \|/
        ●        ← 入口（1層）
```

- ⚠ **層ごとにノードが並び、⚠ 選んだ先で合流する**
- ⚠ **移動回数 ＝ 層数で固定。⚠ どのルートを選んでも必ずボスに着く**
- ⚠ **ルート選択は「どこへ行けるか」ではなく「道中に何を踏むか」の選択**

#### ⚠ これは `DISCUSSION_scenario_map.md` の「合流なし」を覆す

⚠ **メモ（2026-08-23）は「ノードが2分岐でどんどん増えていく構造（合流なし）」と書いている。⚠ 2026-08-25 に人間が合流ありへ変更した。⚠ メモより**この台帳が優先**する。**

⚠ **覆した理由（設計役が指摘し、人間が裁いた）：**

1. ⚠ **「合流なし」と「ボスは固定位置」は両立しない。** ⚠ **合流が無いと n 段で葉が 2^(n-1) 個でき、⚠ ボスに繋がる葉は1つだけ。⚠ 残りは全部行き止まりになり、⚠ 「引き返せない一本道」の前提では詰む**
2. ⚠ **「合流なし」と「たいまつ（視界）」も噛み合わない。** ⚠ **倍々に増えるのはルートの総数であって、⚠ プレイヤーが実際に選ぶのは毎回2択。⚠ 2択の先が見えるかどうかに高い金は払わない＝たいまつを買い替える価値が出ない**
3. ⚠ **層構造なら移動回数が層数で固定されるので、⚠ 宝箱の期待値が閉じ（§4-3）、⚠ 周回の自動処理（§6）が「各層で1回抽選」で素直に書ける**

⚠ **平面グリッド（ダンジョンらしい探索）も検討したが採らなかった。⚠ 難ダンジョン側の形として取っておく**（§12）。

### 3-3. 層数とノード数

| | 値 | 決め方 |
|---|---|---|
| ⚠ **層数** | ⚠ **5**（推奨値） | ⚠ **いまの1周が5ウェーブなので体感の長さを揃えられる。⚠ 数値なので後から調整できる＝§10-2** |
| ⚠ **1層あたりのノード** | ⚠ **2〜3**（推奨値） | ⚠ **同上** |
| ⚠ **ボス** | ⚠ **最終層の先に1つ。⚠ 全ルートがここへ入る** | ⚠ **固定** |

⚠ **フロアごとに層数を変えるかは後で決める（§10-2）。**

### 3-4. ノード4種

| ノード | 中身 | ⚠ **周回時** |
|---|---|---|
| ⚠ **戦闘** | ⚠ **敵と戦う（基本のマス）。⚠ いまの `waves` 1本ぶんに相当** | ⚠ **結果のみ確定** |
| ⚠ **ショップ** | ⚠ **①入店時に無料ガチャ1回（恒久資産・持ち帰れる）②恒久通貨で消耗品（フロア内専用・持ち帰り不可）③たいまつ購入** | ⚠ **無料ガチャだけ自動処理。⚠ 購入は発生しない** |
| ⚠ **バフ選択** | ⚠ **2〜3択。⚠ フロア内限定の一時強化＝**レリック**（⚠ **§5-2**） | ⚠ **発生しない**（無意味なため） |
| ⚠ **休憩** | ⚠ **HP回復のみ**（まずはシンプルに） | ⚠ **発生しない** |

⚠ **休憩が意味を持つには HP をフロア内で持ち越す必要がある（§2 の最終行）。⚠ 新しい器。**

## 4. 宝箱の作り直し

### 4-1. ⚠ いまの宝箱（**実コード**）

- ⚠ **積む口は `grant_chest()` の1本。⚠ 戦闘（`_grant_stage_chest`）もポモドーロの加護（`claim_pending_chests`）もここを通る**
- ⚠ **`chests.json` は7件。⚠ `generic` / `bonus_small` / `bonus_medium` / `bonus_large`（固定報酬・⚠ 中身は4件とも `construction_material_1` だけ）＋ `stage_1..3`（抽選・⚠ 中身は装備のみ）**
- ⚠ **「3割の周でしか出ない」の正体は、⚠ 抽選表のハズレ枠 `{"item_id": "", "weight": 70}`。⚠ これを引くと `_is_rewards_empty()` が真になり、⚠ `grant_chest()` が `false` を返して宝箱そのものを積まない**（`game_manager.gd:930`）
- ⚠ **中身は積むときに振って個体に焼き込む。⚠ 開けるときには振らない**
- ⚠ **個体は `PENDING_CHESTS` に `{instance_id, chest_id, source, obtained_at, opened, rewards}` で溜まる**

### 4-2. 決まったこと

1. ⚠ **ハズレ枠（`weight: 70` の空欄）を廃止する。⚠ 宝箱が出ると決まったら必ず中身がある**
2. ⚠ **`chest_id` は「フロア × レアリティ」にする**。⚠ **`floor_1_common` / `floor_1_rare` / `floor_1_epic` / `floor_1_legendary` … の形**
3. ⚠ **5フロア × 4段階 ＝ 20件。⚠ 既存の `generic` / `bonus_*` の4件はそのまま残す**（⚠ **ポモドーロの加護が使っている**）
4. ⚠ **深度補正は「どの `chest_id` を積むか」を呼ぶ側で選ぶ**。⚠ **`_roll_weighted_table()` は触らない**
5. ⚠ **溜める方式は変えない**（`PENDING_CHESTS` を通す）。⚠ **副産物として宿題23（戦闘結果に宝箱が出ない）は「マップ上に出る」で解消する**
6. ⚠ **`name_key` はレアリティ側だけ持つ。⚠ フロアごとに名前を分けない**（⚠ **`ja.csv` は4行で済む**）

### 4-3. ⚠ ハズレ枠を廃止した帰結（**一番大きい**）

⚠ **いまは「7割の周で宝箱そのものが積まれない」ことが、⚠ 宝箱の量を絞る唯一の栓になっている。⚠ 廃止すると栓が消える。**

- ⚠ **新しい栓は「移動あたりの出現確率」**（メモの「移動に紐づく抽選」）
- ⚠ **1周あたりの宝箱数 ＝ 移動回数 × 出現確率。⚠ 層構造なので移動回数＝層数で固定＝期待値が閉じる**（⚠ **§3-2 で合流ありを選んだ理由の3つ目**）
- ⚠ **`_is_rewards_empty()` の枝は残す**（保険。⚠ ただし平常系では二度と通らなくなる）
- ⚠ **`scenario=economy` の「1周で入るもの」が全部動く。⚠ 数値を入れる段で必ず回し直す**

### 4-4. ⚠ 1フロア最低1回の保証

⚠ **メモの「クリアまでに一度も当たらなければ確定発生させる」。⚠ フロア内にカウンタが要る**（§7 の状態キー）。

### 4-5. ⚠ レアリティは開封前から見える

⚠ **色・エフェクトで示唆する。⚠ 隠さない。**
⚠ **「奥ほど良い物が出やすい」は隠しパラメータにせず、⚠ 画面かテキストで明示する**（メモの明文化要求）。

## 5. 視界（たいまつ）

⚠ **層構造（§3-2）を採ったので、⚠ 視界は「半径」ではなく「何層先まで中身が見えるか」になる。**

- ⚠ **基本は次の1層しか中身が見えない**（⚠ **その先はノードがあることは分かるが種類が伏せられている**）
- ⚠ **ボスの位置だけは常に見えている**
- ⚠ **たいまつのグレードが上がるほど、⚠ 先の層まで種類が見える**
- ⚠ **たいまつ＝フロア内状態**（決定3）。⚠ **アイテムにしない。⚠ 倉庫にも図鑑にも出ない**
- ⚠ **持つのはグレード番号1つだけ**（§7）
- ⚠ **ショップノードでのみ買い替えられる。⚠ 上限グレードあり**
- ⚠ **フロアごとにリセット。⚠ クリアでも敗北でも、⚠ 次のフロアは基礎のたいまつから**

⚠ **設計役の指摘（人間が了承済み）：⚠ 層構造ではたいまつの価値が平面マップより弱い。⚠ 「負けてもノーリスク」の場所で高い買い物をする理由が出にくいため。⚠ たいまつを主役にするなら、⚠ それは難ダンジョン側の看板になる**（§12）。
⚠ **たいまつのグレード数・価格・見える層数は後で決める**（§10-2 の5）。

### 5-2-2. ⚠ なぜ恒久にしないか

1. ⚠ **周回は自動スキップする前提（§6）なので周回数が伸びる。⚠ 恒久レリックはそこで即座に破綻する**
2. ⚠ **恒久にすると「一度揃えたら終わり」になり、⚠ 周回が今と同じ作業に戻る。⚠ 「わくわくが足りない」への回答にならない**
3. ⚠ **§3-4 で「フロア内限定のもの（バフ選択・休憩・消耗品）は周回で発生しない」と既に決めてある。⚠ ここに入れれば新しい例外を作らずに済む**
4. ⚠ **恒久にするなら「装飾（`part` 61件・枠に刺す）と何が違うのか」に先に答える必要がある**

⚠ **たいまつとの依存**：⚠ **§5 で「層構造だとたいまつが弱い」と指摘した。⚠ レリックが積み上がる構造なら「先を見て良いバフノードを狙う」に金を払う理由が生まれる。⚠ たいまつの価値はレリックの強さで決まる。⚠ 数値を決めるときはこの2つを一緒に見ること。**
