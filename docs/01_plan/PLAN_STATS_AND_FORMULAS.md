# ステータスと計算式 設計チェックリスト

**このファイルは「どの軸があって、どう計算するか」だけを持つ。** 何を消費して強くなるかは`PLAN_CHARACTER_GROWTH_LOOP.md`。

**装備の第2弾より先にここを決める。** セーブの`stats`にキーが増えるため、構造を触る1回に乗せるしかない。

---

## 0. なぜいま決めるのか

**触れる軸が4本しかない。**

| | いまの持ち主 | 装備・研究で動くか |
|---|---|---|
| `hp` `atk` `def` `spd` | `character_growth.stats` | ✅ 動く |
| `attack_range` `attack_interval_sec` | `characters.json`（マスター直読み） | ❌ 動かない |
| スキルの`multiplier` `cooldown_sec` | `skills.json` | ❌ 動かない |

**宝石を作るのに軸が4本だと、「atkの大・中・小」を並べることになる。** 5部位×2枠＝10枠に対して選ぶ意味が生まれない。

**装備を作ってから増やすと、宝石の種類が4軸に縛られたまま固まる。**

## 1. 軸の一覧

- [x] **9軸＋固定の`spd`で確定**

| キー | 種類 | 計算 | 上限 |
|---|---|---|---|
| `hp` | 実数 | 加算 | 不要 |
| `atk` | 実数 | 加算 | 不要 |
| `mag`（魔力） | 実数 | 加算 | 不要 |
| `def` | 実数 | 除算（下記2-2） | **不要**（式が逓減する） |
| `atkspd`（攻撃速度） | ％ | 除算（下記2-1） | **要る** |
| `haste`（クールダウン短縮） | ％ | 除算（下記2-1） | **不要**（式が逓減する） |
| `crit_rate` | ％ | 抽選 | **要る（100%）** |
| `crit_dmg` | ％ | 倍率 | 不要 |
| `spd`（移動速度） | 実数 | そのまま | 不要 |

- [x] **`spd`は固定。** `growth_per_level`を0にし、`spd`を上げる宝石を作らない
- [x] **`spd`を`stats`から抜かない。** 抜くと既存セーブの`spd`が宙に浮く。`characters.json`の値がそのまま毎回使われる形にしておけば、後から動かしたくなったときも数字を入れるだけで済む
- [x] **実数も％も同じ`stats`辞書に入れ、`_stat_keys()`の配列に9個並べる**
- [x] **％は`int`で持つ**（`crit_rate: 25` ＝ 25%）。`float`で持つと`.0`が乗る

> **`_stat_keys()`に足すだけで、レベル・研究・装備・宝石の合成が全部追従する。** `_recalc_stats()`も`get_effective_stats()`も`get_equipment_bonus()`も、全部この配列をループしている。

## 2. 計算式

**式は`.gd`に書く。`.tres`の文字列にしない。**

`character_config.gd`の`stat_growth_formula`はExpressionを文字列で持っているが、**あれはレベルアップの瞬間にしか走らない。攻撃間隔とクールダウンは毎フレーム参照される。**

### 2-1. ％で短縮するもの

- [x] **攻撃速度とクールダウン短縮は同じ形にする**

```
攻撃間隔   = base_attack_interval_sec / (1 + atkspd / 100)
クールダウン = base_cooldown_sec        / (1 + haste  / 100)
```

> **LoLのアビリティヘイストと同じ形。** 加算で積んでも0秒に到達しないので、上限が無くても壊れない。「短縮率40%」方式だと100%で除算0になり上限が要る。**上限に当たったぶんの装備が無駄になる＝後悔する。**

> **同じ形を2箇所で使えば、プレイヤーが覚える規則も1つで済む。**

### 2-2. 防御

- [x] **除算にする**

```
被ダメージ = damage × 100 / (100 + def)
```

> **減算（`atk - def`）にすると破綻する。** いまの敵の攻撃力は8〜12。剣士は素で`def` 6。**`def`を12積んだ瞬間に無敵になる。装備を作る前に壊れる。**

### 2-3. クリティカル

- [x] 上限は**100%**
- [x] **100%を超えたぶんは`crit_dmg`に変換する**

> 変換しないと、超過分の宝石が完全に無駄になる。

> **1戦90秒・攻撃間隔1.2秒なら70発以上入るので、分散は平均に収束する。** クリティカルの分散は「上振れ」なので、出れば嬉しく、出なくても平常運転。

### 2-4. 上限の扱い

- [x] **`get_effective_stats()`は生の合計を返す。上限は使う瞬間に掛ける**

理由は2つ。

**上限値を変えたときに既存セーブが自動で追従する**（研究・装備で3回使っている「状態にはIDと数字だけ」と同じ考え方）。

**育成画面で「`atkspd` 250%（上限200%）」と出せる。** 丸めた値だけ持っていると、プレイヤーは上限に当たっていることに気づけない。**気づかずに宝石を刺し続けるのが、いちばん後悔する形。**

- [ ] 上限値を置く`.tres`を作る（`StatConfig`など）。`max_attack_speed_percent` / `max_crit_rate` / `min_attack_interval_sec`
- [ ] ％系の上限を全部100に揃えるか、軸ごとに変えるか

> **`atkspd` 100%は「攻撃間隔が半分」。** 剣士なら1.2秒→0.6秒。`crit_rate`の100%と数字が揃うので、プレイヤーが覚える上限が1つで済む。

> **`atkspd`にだけ上限が要る理由は式ではない。** 除算なので0秒には届かないが、**間隔が短くなりすぎると当たり判定とアニメーションが破綻する。**

## 3. 入れないと決めたもの

**議論して落とした。理由を残す。同じ提案が次の会話で出るため。**

| 軸 | 落とした理由 |
|---|---|
| **ライフスティール** | オートバトルでは攻撃時間が9割を超えるので、`hp_regen`を全ての場面で上回り、片方が必ず死に軸になる。**そして剣士の生存が剣士で完結すると、僧侶の存在意義が薄くなる** |
| **HP自動回復** | 上記の裏返し。5ウェーブ連戦でHPを引き継ぐ設計のため、ウェーブ間に効くなら僧侶の代替になり、戦闘中だけなら誤差 |
| **回避** | 分散の向きが「下振れ」。避けたことには気づかず、**避けなかったときだけ「運が悪かった」と感じる。** オートバトルなのでリカバリーの余地が無い。**`def`を除算にした以上、2本目の減算経路になる** |
| **属性防御** | 意味を持つのは「ステージごとに正解の装備が変わる」ときだけ。**装備は個体としてキャラに固定される設計で5部位×3人＝15枠。** 毎回組み替える遊びではない。**「炎耐性の兜を3時間かけて作ったら次は氷だった」が起きる** |

- [x] **ライフスティールと`hp_regen`はキャラのパッシブの候補として残す**（`PLAN_CHARACTER_GROWTH_LOOP.md` 5）
- [x] **回避を入れるとしたら上限20%程度。** 「たまに得する」レベルに抑える
- [x] **属性は、やるならパーティ編成で対応する形。** その場合ステータス軸としては要らない
