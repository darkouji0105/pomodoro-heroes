# 【作戦計画書】UI共通パーツ

第2層・作戦計画。画面ごとの詳細レイアウトは対象外（各画面の実装直前でよい）。ここでは「どの画面でも使い回す土台」だけを決める。

---

## 1. Theme リソース

- `res://theme/main_theme.tres` を作成し、Project Settings → GUI → Theme → Custom でプロジェクト全体のデフォルトThemeとして設定する（各シーンで個別に割り当てない）
- ボタン・パネル・ラベルの基本スタイルはここに一元化する。個別シーンでスタイルを都度作らない

## 2. 配色・フォント（決定済み・差し替え前提）

### コンセプト：トマト（ダークめ）

ポモドーロの語源であるトマトを基調にする。ただし赤を全面に敷くと長時間の作業画面として目が疲れるため、**背景は赤みを帯びた暗色にとどめ、彩度の高い赤はボタンなど「押す場所」に限定する**。

| 用途 | 変数名（Theme内） | カラーコード | 使いどころ |
|---|---|---|---|
| 背景 | `bg_base` | `#1A1418` | 画面全体の下地。熟したトマトの影 |
| パネル | `bg_panel` | `#2A1F24` | ウィンドウ・カード・ダイアログ |
| プライマリ | `primary` | `#C4453A` | 主要ボタン、重要な要素 |
| プライマリ濃 | `primary_dark` | `#8E2F28` | ボタン押下時、影 |
| アクセント | `accent` | `#6B8F3F` | 報酬・成功・完了（ヘタの緑） |
| テキスト | `text_main` | `#F0E6E0` | 通常の文字。温かみのある白 |
| テキスト薄 | `text_muted` | `#9A8A88` | 補足、無効状態 |
| 警告 | `warning` | `#D98C3A` | 注意喚起（熟しかけのオレンジ） |

**赤と緑は補色関係**にあるため、報酬表示の緑がよく目立つ。`CONCEPT.md`の設計原則「頑張る楽しさを素直に嬉しい手応えとして返す」に沿った配色として意図的に選んでいる。

### フォント

- **Noto Sans JP**（暫定）。日本語対応必須のため
- `res://assets/fonts/` に配置し、`main_theme.tres` の Default Font に1箇所だけ指定する
- **差し替え前提**：ゲームのアセット（キャラ・施設の絵）が決まった段階で、雰囲気に合うフォントへ変更する。Theme1箇所の変更で全画面に反映される状態を保つこと

### 運用ルール

- **個別シーンに色やフォントを直接ハードコードしない。** 必ずThemeを経由する
- 上の色も含め、変更は`main_theme.tres`の1箇所で完結させる
- スクリプト内で色が必要な場合（動的な色変更等）は、`Color("#C4453A")`のような直書きではなく、Themeから取得するか、定数として1箇所にまとめる

## 3. 共通コンポーネント一覧（再利用シーンとして切り出す）

※ ファイル名はsnake_case、ルートノード名はPascalCase（`AGENTS.md`命名規則）。例：`primary_button.tscn`のルートノードは`PrimaryButton`。

| コンポーネント名 | 用途 | 使用箇所の例 |
|---|---|---|
| `primary_button.tscn` | 標準ボタン | 全画面の確定・遷移ボタン |
| `resource_display.tscn` | アイコン＋数値の表示 | 拠点下部（gold/stamina/建築素材） |
| `dialog_base.tscn` | オーバーレイの共通土台 | 施設別ウィンドウ、確認ダイアログ |
| `cooldown_button.tscn` | クールダウン付きボタン | 戦闘画面のスキルボタン ※**後回し**（下記参照） |
| `notification_label.tscn` | 簡易通知・リアクション表示 | 拠点のキャラタップ時の吹き出し ※**後回し**（下記参照） |

### 今回作るもの／後回しにするもの

**今回作る**：`main_theme.tres` / `primary_button.tscn` / `resource_display.tscn` / `dialog_base.tscn`

**後回し**：`cooldown_button.tscn`（戦闘画面の実装時）、`notification_label.tscn`（拠点画面の実装時）

理由：この2つは使う場面が1つしかなく、実際の画面を作るまで必要な仕様（クールダウンの表示方法、吹き出しの追従挙動など）が確定しない。先に作ると仕様が変わって作り直しになるため、**その画面のEXECを書くときに一緒に設計する**。共通パーツとして切り出す価値があると分かった時点で`components/`へ移す。

## 4. 配置ルール

`AGENTS.md`のフォルダ構造に反映済み。

```
res://
├── theme/
│   └── main_theme.tres   # 配色・フォント・基本スタイル
└── scenes/
	├── ui/
	│   └── components/   # 2画面以上で使い回すUIパーツのみ
	├── title/
	├── base/
	├── guild/
	├── adventure/
	└── pomodoro/
```

### `components/` に入れてよいものの基準

**2つ以上の画面で使うパーツだけ**を置く。1画面でしか使わないものは、その画面のフォルダに置く。

| 例 | 置き場所 | 理由 |
|---|---|---|
| `primary_button.tscn` | `scenes/ui/components/` | 全画面の確定・遷移ボタンで使う |
| `dialog_base.tscn` | `scenes/ui/components/` | 施設ウィンドウ・確認ダイアログ等で使う |
| `timer_display.tscn` | `scenes/pomodoro/` | ポモドーロ以外で使わない |
| `unit_view.tscn` | `scenes/adventure/` | 戦闘画面以外で使わない |
| `research_node.tscn` | `scenes/guild/` | 研究画面以外で使わない |

**迷ったら画面フォルダに置く。** あとで他画面でも必要になった時点で`components/`へ移せばよい。逆（共通に置いたが1画面でしか使われない）のほうが、あとで整理しにくくなる。

> この基準を緩めると`components/`が「なんとなくUIっぽいもの置き場」になり、本当に共通のパーツを探せなくなる。`AGENTS.md`「UIパーツの置き場所ルール」にも同内容を記載済み。
