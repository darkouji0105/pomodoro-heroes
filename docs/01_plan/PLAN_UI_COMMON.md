# 【作戦計画書】UI共通パーツ

第2層・作戦計画。画面ごとの詳細レイアウトは対象外（各画面の実装直前でよい）。ここでは「どの画面でも使い回す土台」だけを決める。

---

## 1. Theme リソース

- `res://theme/main_theme.tres` を作成し、Project Settings → GUI → Theme → Custom でプロジェクト全体のデフォルトThemeとして設定する（各シーンで個別に割り当てない）
- ボタン・パネル・ラベルの基本スタイルはここに一元化する。個別シーンでスタイルを都度作らない

## 2. 配色・フォント（プレースホルダー・要確定）

世界観・トーンが未確定のため、ここは仮値で進めて後日差し替える。

| 用途 | 仮の値 |
|---|---|
| プライマリカラー | 未定（後日差し替え） |
| アクセントカラー | 未定 |
| 背景色 | 未定 |
| テキスト色 | 未定 |
| 警告・エラー色 | 未定 |
| フォント | 日本語対応必須（候補：Noto Sans JP等）、Theme側で1箇所指定 |

**運用ルール**：これらが未確定のうちは仮の色（グレー等）で進めてよい。後で「Theme一箇所を差し替えるだけで全画面に反映される」状態を保つのが目的なので、個別シーンに直接色をハードコードしない。

## 3. 共通コンポーネント一覧（再利用シーンとして切り出す）

※ ファイル名はsnake_case、ルートノード名はPascalCase（`AGENTS.md`命名規則）。例：`primary_button.tscn`のルートノードは`PrimaryButton`。

| コンポーネント名 | 用途 | 使用箇所の例 |
|---|---|---|
| `primary_button.tscn` | 標準ボタン | 全画面の確定・遷移ボタン |
| `resource_display.tscn` | アイコン＋数値の表示 | 拠点下部（gold/stamina/建築素材） |
| `dialog_base.tscn` | オーバーレイの共通土台 | 施設別ウィンドウ、確認ダイアログ |
| `cooldown_button.tscn` | クールダウン付きボタン | 戦闘画面のスキルボタン |
| `notification_label.tscn` | 簡易通知・リアクション表示 | 拠点のキャラタップ時の吹き出し |

## 4. 配置ルール

`AGENTS.md`のフォルダ構造に反映済み。

```
res://
├── theme/
│   └── main_theme.tres   # 配色・フォント・基本スタイル
└── scenes/
    ├── ui/
    │   └── components/   # 2画面以上で使い回すUIパーツのみ
    ├── title/
    ├── base/
    ├── guild/
    ├── adventure/
    └── pomodoro/
```

### `components/` に入れてよいものの基準

**2つ以上の画面で使うパーツだけ**を置く。1画面でしか使わないものは、その画面のフォルダに置く。

| 例 | 置き場所 | 理由 |
|---|---|---|
| `primary_button.tscn` | `scenes/ui/components/` | 全画面の確定・遷移ボタンで使う |
| `dialog_base.tscn` | `scenes/ui/components/` | 施設ウィンドウ・確認ダイアログ等で使う |
| `timer_display.tscn` | `scenes/pomodoro/` | ポモドーロ以外で使わない |
| `unit_view.tscn` | `scenes/adventure/` | 戦闘画面以外で使わない |
| `research_node.tscn` | `scenes/guild/` | 研究画面以外で使わない |

**迷ったら画面フォルダに置く。** あとで他画面でも必要になった時点で`components/`へ移せばよい。逆（共通に置いたが1画面でしか使われない）のほうが、あとで整理しにくくなる。

> この基準を緩めると`components/`が「なんとなくUIっぽいもの置き場」になり、本当に共通のパーツを探せなくなる。`AGENTS.md`「UIパーツの置き場所ルール」にも同内容を記載済み。
