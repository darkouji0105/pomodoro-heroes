## 2. 画面構成（SCENES.mdより）

- 遷移元：ギルド画面
- タブ：日替わり／週替わり／月替わり

---

## 3. データ（DATA_SCHEMA.md 4-2より）

- `daily_shop` / `weekly_shop` / `monthly_shop`：ギルド側のデータ。GameManagerへの保持を提案（倉庫の`codex`と同様の方針）
- 各ラインナップは`slot_id` / `item_id` / `cost` / `stock_limit` / `purchased_count`を持つ

---

## 4. UIロジック概要

- タブ切り替えで対応する`line_up`を表示
- 各スロット：
  - `purchased_count >= stock_limit`なら「売り切れ」表示、購入不可
  - タップで購入確認 → 所持金（`cost.currency_type`に応じてgold/gems等）が足りるか確認
  - 購入成立で`add_to_inventory()` + `purchased_count`を+1
- `refresh_at`を過ぎたら該当タブのラインナップを再生成（生成ロジックの詳細は下記6参照）

---

## 5. GameManagerへの反映（対応済み）

`PLAN_COMMON_INFRA.md`のGameManagerに以下を反映済み：
- 日替わり／週替わり／月替わりのショップデータをGameManagerが持つ永続データに含めた
- 指定したショップ種別の現在のラインナップを取得できる（`get_shop_lineup`）
- 商品を購入できる。残高不足・売り切れなら何もせず失敗を返す（`purchase_shop_item`）
- 補充タイミングを過ぎていればラインナップを再生成する（`refresh_shop_if_needed`）

---

## 6. 未確定・要決定

- ラインナップの再生成ロジック（ランダム抽選の対象アイテムプール・重み付け）→ `Balance`（`ShopConfig`）側に定義するのが望ましいが、詳細な抽選テーブルは未設計
- `refresh_at`の判定タイミング（アプリ起動時にまとめてチェックするか、ショップ画面を開くたびにチェックするか）
  - なお「1日」の区切りは毎朝4:00で確定済み（`DATA_SCHEMA.md` 2-4）。日替わりショップのリフレッシュ判定も、ポモドーロ・ストリークと同じ共通ヘルパー（`GameDate`）を使い、基準がズレないようにすること
- 購入時のアニメーション・演出
