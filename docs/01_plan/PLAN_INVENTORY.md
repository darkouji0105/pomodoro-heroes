## 2. ⚠ いま実コードにあるもの（**2026-09-02 に `grep` で取った**）

### 2-1. ⚠ 物は**4つの別々の入れ物**に分かれている

| # | 入れ物 | 形 | いまの表示 |
|---|---|---|---|
| **①** | `MATERIALS` | `{material_id: int}` | ⚠ **拠点の下段に「名前 と 数」で並ぶ**（16件・数千個になる） |
| **②** | `INVENTORY` | `{item_id: {count, type, slot_position, properties}}` | 倉庫の持ち物タブ（装飾・消耗品） |
| **③** | `EQUIPMENT_INSTANCES` | `{instance_id: {item_id, grade, parts}}` | ⚠ **同じタブの後ろに続けて並ぶ**（個体なので数えられない） |
| **④** | `DUNGEON_RUN_BAG` | `{item_id: int}` | ⚠ **17-d で作った画面に「回薬 x1」の行で出る**（枠は個数で数える） |

⚠ **マス目にするとき、この4つを1枚の器に混ぜるかどうかが最初の分かれ道**（§5 の未決1）。

### 2-2. ⚠ **`slot_position` の欄は在るが、誰も使っていない**

- ⚠ `INVENTORY` の各エントリは `slot_position: {x, y}` を**最初から持っている**（`add_to_inventory()` が `{0,0}` で埋める）
- ⚠ `GameManager.update_inventory_slot_position()` も**在る**。⚠ **呼び出し元は0件**
- → ⚠ **「マス目に置いた場所を覚える器」だけが先にあって、⚠ 一度も使われていない**
  （`AGENTS.md`「欄だけ足して実装しない」に既に引っかかっている状態）

⚠ **並べ替えを作るならこの欄を生かす。⚠ 作らないなら欄ごと消す。⚠ 放置しない。**

### 2-3. ⚠ ドラッグ＆ドロップは**0件**

⚠ `_get_drag_data` / `_can_drop_data` / `_drop_data` が**プロジェクト全体で1つも無い**。⚠ **ゼロから作る。**

### 2-4. ⚠ 物が増える口（**容量を持たせると、全部が「入らない」を返せる形になる**）

⚠ **個体化の口は `add_to_inventory()` の1本**（CLAUDE.md 8番）。⚠ **そこへ流れ込む呼び元は6本**：

| # | 呼び元 | 何が入る |
|---|---|---|
| 1 | **宝箱を開ける**（`open_chest`） | 装備・装飾・消耗品 |
| 2 | **ショップの購入**（`purchase_shop_item`） | 同上 |
| 3 | **作業場の受け取り**（`collect_craft`） | 装飾 |
| 4 | **装飾の段階上げ**（2箇所） | 装飾 |
| 5 | **ポモドーロの報酬** | スタミナポーション |
| 6 | ⚠ **ダンジョンからの撤退**（`retreat_from_dungeon` → `_grant_item`） | ランで拾ったもの |

⚠ **素材（`add_material`）はこの6本の外**。⚠ **別の口で、別の入れ物に入る。**

## 3. マス目にすると**自動的に決まってしまうこと**

| | どうなるか |
|---|---|
| **マス目 ＝ 有限** | ⚠ **「入らない」が必ず起きる。⚠ §2-4 の6本すべてに行き先が要る**（§4） |
| ⚠ **スタックしない（決定3）** | ⚠ **1マス＝1個。⚠ 素材2999個 = 2999マス になる。⚠ 素材と消耗品をマスに入れると即破綻する**（§5 の未決1） |
| **並べ替え** | ⚠ **保存するなら `slot_position` を使う。⚠ 使うなら「マスの穴あき」を状態が持つことになり、⚠ `add_to_inventory()` が「空きマスを探す」責任を持つ** |
| **装備の個体** | ⚠ **1個＝1マス（数えられないので当然そうなる）。⚠ 等級10の剣を10本持つと10マス** |

## 4. ⚠⚠ 「倉庫にも容量」が要求する裁き（**決定2 の代償。⚠ ここが本体**）

⚠ **`PLAN_HARD_DUNGEON.md` §4-1 は「拠点の倉庫を有限にすると育成が詰む」と書いて無限にした。**
⚠ **覆したので、⚠ 詰まないことを別の形で保証する必要がある。**

### 4-1. ⚠ 溢れたときの行き先を、6本すべてで決める

| 呼び元 | 溢れたら | ✅ **入れた形**（2026-09-03・18-b） |
|---|---|---|
| **宝箱を開ける** | ⚠ 開けてから溢れると中身が消える | ✅ **開けさせない**（`pending_chests` に未開封のまま残る）。⚠ **中身が素材だけの宝箱は満杯でも開ける**（⚠ マスを使わないため。⚠ ここを締めると理由なく開けなくなる） |
| **ショップの購入** | ⚠ ゴールドを払ってから消える | ✅ **買わせない**（⚠ 判定は「ここから状態を変える」の手前。⚠ 素材で受け取る枠はマスを使わないので弾かない） |
| **作業場の受け取り** | ⚠ キューから消えてから溢れる | ✅ **受け取らせない**（⚠ 完成済みのままキューに残る）。⚠ **抽選ぶんは `rolls` の数だけ多めに要求する**（⚠ 引く前に中身が分からないため） |
| ⚠ **装飾の段階上げ** | — | ⚠⚠ **溢れない。⚠ 手を入れていない**（⚠ **`upgrade_part()` / `merge_runes()` は「複数消して1個足す」＝マスは純減する**）。⚠ **初版で「一番危ない経路」と書いたのは誤り＝実コードを読んで分かった** |
| **ポモドーロの報酬** | ⚠⚠ **集中した時間が無駄になる** | ✅⚠ **入らなかったぶんを「集中の端数」（`POTION_FOCUS_REMAINDER`）へ戻す**。⚠ **倉庫を空ければ次のポモドーロで受け取れる。⚠ ここだけ押し戻す先がある**（⚠ 初版の推奨「消耗品はマスの外」は決定5 で消えたので、⚠ 別の解き方に差し替えた） |
| **ダンジョンの撤退** | ⚠ ランの成果が消える | ✅ **入るぶんだけ持ち帰り、⚠ 残りは戻り値の `left_behind` に出す**（⚠ 黙って消さない）。⚠ **素材はマスを使わないので必ず持ち帰る** |

⚠ **どれも「状態を触る前に判定を終える」**（CLAUDE.md 6番）。⚠ **払ってから弾くと壊れる。**
⚠ **最後の砦は `add_to_inventory()`**（⚠ 入る数まで削って `W25` を出す）。⚠ **ただしそこは判定の場所ではない。**

### 4-3. ⚠ 装備マスへ移る（**人間の決定7・2026-09-03**）

⚠ **「キャラに装備する」＝ インベントリのマスから出て、⚠ キャラの装備マス（5枠）へ移る。**

| | マスの増減 | 判定が要るか |
|---|---|---|
| ⚠ **着ける** | ⚠ **インベントリ −1**（⚠ **前に着けていたものが戻るなら差し引き 0**） | ⚠ **要らない**（⚠ 増えないため） |
| ⚠⚠ **外す** | ⚠ **インベントリ +1** | ⚠⚠ **要る＝7本目の口**（⚠ **満杯なら外させない。⚠ 外してから置き場が無いと個体が宙に浮く**） |

⚠ **同じ個体が2箇所に出ないこと**：⚠ **`get_inventory_slot_entries()` は装備中を除き、
⚠ `get_equipment_slot_entries(character_id)` が5枠を返す**（⚠ **空の枠も返す**）。
⚠ **両方に出すと1個で2マスを占めているように見え、⚠ 数も合わなくなる。**

### 4-2. ⚠ 詰まないことの保証

- ⚠ **拡張の口を必ず用意する**（決定2「拡張可能にする」）。⚠ **ゴールドか研究か。⚠ 未決2**
- ⚠ **捨てる口を必ず用意する**（⚠ 満杯で拡張も買えないと閉じ込められる。⚠ Roguebook の知見＝`PLAN_HARD_DUNGEON.md` §4-2 と同じ形）
- ⚠ **初期の枠は「いま遊ぶと何マス使うか」を実測してから決める**（⚠ `scenario=layout` が持ち物を73種類入れて測っている。⚠ そこが基準）

### 6-3. ⚠⚠ `slot_position` は使えなかった（**2026-09-03・18-f で分かった**）

⚠ **`INVENTORY` の `slot_position` は「item_id ごとに1つ」。**
⚠ **人間の決定3「重ねない（1マス＝1個）」だと、⚠ ポーション5個は5マスなのに位置は1つしか持てない。**
→ ⚠ **表現できないので使わない。⚠ 欄と `update_inventory_slot_position()` は消した**（⚠ **呼び出し元は元から0件**）。

⚠ **代わりに `INVENTORY_ORDER`（トップレベル・1本）を立てた**：

| | |
|---|---|
| **形** | ⚠ **長さ＝倉庫のマス数の配列。⚠ 1要素＝1マス。⚠ `""` は空きマス** |
| **中身** | ⚠ **持ち物なら `item_id`（同じIDが個数ぶん並ぶ）／ 装備の個体なら `instance_id`** |
| ⚠⚠ **正ではない** | ⚠ **持ち物そのものは `INVENTORY` と `EQUIPMENT_INSTANCES` が正。⚠ 並びは「飾り」。⚠ 食い違ったら並びのほうを作り直す**（`_reconciled_inventory_order()`） |
| **作り直しの規則** | ⚠ **拾ったもの＝前から空きマスへ ／ 無くなったもの＝マスを空ける ／ ⚠ 穴は詰めない**（⚠ **詰めると自分で空けた場所が消える＝動かせないのと同じ**） |
| **動かす口** | ⚠ **`move_inventory_slot(from, to)` の1本。⚠ 交換（swap）。⚠ 挿入にしない** |

### 6-4. ⚠⚠ 実機で見つかった穴（**2026-09-03・人間が見つけた**）
