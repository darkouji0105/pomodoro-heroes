## 1. ループの全体像

```
戦闘に勝つ（ステージ1〜3）
  ├─ gold ──────────→ ショップで素材を買う
  ├─ training_material ─→ 育成でレベルを上げる
  ├─ construction_material → 研究で上限を解放する／作業場で装備を作る
  └─ forging_material_1 ─→ 鍛冶で装備の等級を上げる

ポモドーロで働く
  ├─ 作業25分ごと → スタミナポーション1個（+50）
  └─ 加護のしきい値 → 宝箱（中身は construction_material のみ）

スタミナ → ステージに挑む（勝ったときだけ5消費）
```

### 素材の蛇口と出口（1対1になっているか）

| 素材 | 蛇口（入る場所） | 出口（使う場所） | 対応 |
|---|---|---|---|
| `training_material` | ステージ 2/4/6、ショップ（10個300G・30個800G）、作業場（建築30→育成20、建築100→育成80） | **育成のレベルアップのみ** | ✅ 1対1 |
| `construction_material` | ステージ 3/5/8、**宝箱（4/10/25/30）**、ショップ（同額）、作業場（育成30→建築20） | **研究の解放**／**作業場の装備製作**／作業場の素材変換 | ⚠️ 出口が3つで取り合う |
| `forging_material_1` | ステージ 2/4/6、ショップ（10個400G）、作業場（建築30→鍛冶10）、**装備の素材化** | **鍛冶（等級上げ）のみ**／`craft_amulet_life`が5個 | ✅ ほぼ1対1 |
| `gold` | ステージ 50/80/120 のみ | **ショップのみ** | ✅ 1対1 |
| スタミナ | ポモドーロのポーション（25分で1個・+50） | ステージ挑戦（勝利時5） | ✅ 1対1 |

**`construction_material`だけが3方向に取り合っている。** 研究・装備製作・素材変換が同じ財布を見る。`PROJECT_STATUS.md`の未確定表にも「`construction_material`の取り合い」として挙がっている。

**建築素材だけが宝箱から出る。** ポモドーロで直接増えるのは建築素材とスタミナポーションの2つだけ。

## 2. 強化の6軸：それぞれの現状

台帳（`PLAN_CHARACTER_GROWTH_LOOP.md` 0章）の6軸に対応させてある。

| # | 軸 | 状態 | ひとことで |
|---|---|---|---|
| 1 | レベル | ✅ | 動いている。**ただし台帳が決めた「ステータスが上がらない」への転換は未実施** |
| 2 | スキル選択 | 🟡 | 戦闘は2つ撃てるが、**選ぶ機能が空実装で呼び出し元もゼロ** |
| 3 | 研究 | ✅ | 動いている。**ただし台帳が決めた「+1ずつ」は未実施（+5のまま）** |
| 4 | 装備を作る | ✅ | 5部位・個体管理まで完了 |
| 5 | 鍛冶（等級） | ✅ | 動いている。**上限3** |
| 6 | 枠に刺すもの（宝石／ルーン） | 🟡 | **器だけ。しかも上限3なので枠は永久に開かない** |

### 2-1. レベル ✅

- 素材：`training_material`
- コスト：`base_level_up_cost=3` + `cost_growth_per_level=1.0 × (level-1)` → **レベルLから1つ上げるのに `L+2` 個**
  - Lv1→10 で **63個**／Lv1→30 で **493個**（1キャラ）／3人で **1,479個**
- 上限：`base_level_cap`（**10**）＋ 解放済み研究ノードの合計（現在最大**+20**）＝ **30**
- 効果：`hp/atk/def/spd` が `growth_per_level` ぶん上がる（剣士8/2/1/1、弓兵5/2/1/1、僧侶4/1/1/1）
- 計算式は`.tres`に文字列で持ち`Expression`で評価する（`GrowthFormula`）。式は `base + growth * (level - 1)`

**根拠**：[game_manager.gd:923-946](autoload/game_manager.gd#L923-L946)（コスト）、[game_manager.gd:1036-1057](autoload/game_manager.gd#L1036-L1057)（`_recalc_stats`）、[game_manager.gd:1635](autoload/game_manager.gd#L1635)（上限）

**画面**：`scenes/guild/training_screen.gd`。`get_level_up_cost` / `level_up_character` / `get_effective_stats` / `get_effective_level_cap` を呼ぶ。

> **`CHARACTER_IDS`が決め打ち。** `MasterDataLoader`にキャラ一覧を返す関数が無いため（`PROJECT_STATUS.md`の宿題）。

### 2-2. スキル選択 🟡

| もの | 状態 |
|---|---|
| `characters.json`の`skills` | 各キャラ2個入っている |
| 戦闘 | **その2個をそのまま使う。2つ撃てている** |
| `character_growth.skills` | **`{}`のまま。誰も書かない**（[game_manager.gd:1024](autoload/game_manager.gd#L1024)） |
| `select_skill()` | **`print`するだけのダミー**（[game_manager.gd:1474-1475](autoload/game_manager.gd#L1474-L1475)） |
| `select_skill()`の呼び出し元 | **0件**（`.gd`・`.tscn`を全文検索して確認） |

**候補は2個しか無いので、選択が成立しない。** 候補を6個に増やすのと選択機能は同じタスクでやる、と決まっている。

### 2-3. 研究 ✅

- 素材：`construction_material`
- ノードは縦1列5つ。上限解放**+5×4**（20/40/70/110）＋ 全ステータス**+3**（30）。**合計270で全解放**
- 効果は保存せず、`research_tree`を毎回走査して計算する（[game_manager.gd:1635](autoload/game_manager.gd#L1635) / [:1654](autoload/game_manager.gd#L1654)）
- マスターと状態の同期：起動時・ロード時に`research.json`から流し込み、`unlocked`フラグだけ残す。**JSONを直すと既存セーブにも次の起動で反映される**

**全ステータス+3は戦闘にも効いている。** 装備の第1弾で`battle_controller.gd`を`get_effective_stats()`経由に直した副作用。それ以前は育成画面にしか出ていなかった。

### 2-4. 装備を作る ✅

**5部位**（頭 / 上半身 / 下半身 / 武器 / アクセサリー）。内部キーは`head` / `armor` / `legs` / `weapon` / `accessory`（[game_manager.gd:1064-1071](autoload/game_manager.gd#L1064-L1071)）。

**装備は「個体」として持つ。** `equipment_instances`に`eq_N`として入る。持っているのは`item_id` / `grade` / `parts`の3つだけで、**性能値は保存しない**（[game_manager.gd:1096-1116](autoload/game_manager.gd#L1096-L1116)）。

```json
"equipment_instances": {
  "eq_7": { "item_id": "armor_iron_helm", "grade": 2, "parts": [null, null] }
}
```

**個体を作るのは`add_to_inventory()`の中の1箇所だけ。** `_create_equipment_instance()`の呼び出し元が1件であることを確認済み（[game_manager.gd:309](autoload/game_manager.gd#L309)）。新しい入手経路を足すときは必ずここを通す。

**在庫（`inventory`）とは混ぜない。** 装備中の個体も`equipment_instances`に残り、出し入れしない。

#### 装備の一覧（`items.json`・11種）

| 部位 | アイテム | 性能（等級1） |
|---|---|---|
| 武器 | 木の剣 / 鉄の剣 / 鋼の剣 | atk 3 / 8 / 15 |
| 頭 | 革の帽子 / 鉄の兜 | def2 ／ hp10 def5 |
| 上半身 | 革の胴着 / 鉄の鎧 | hp15 def4 ／ hp30 def9 |
| 下半身 | 革のブーツ / 鉄の具足 | spd4 ／ def4 spd2 |
| アクセサリー | 力の指輪 / 生命の護符 | atk4 ／ hp25 |

#### 入手経路（3つのうち実際に機能しているのは1つ）

| 経路 | 状態 |
|---|---|
| **作業場で作る** | ✅ レシピ10件（木剣・革帽・革靴・革胴着・力の指輪・鉄剣・鉄兜・鉄鎧・鉄具足・命の護符） |
| **宝箱から出る** | 🟡 **仕組みだけ。** `ChestContentConfig.equipment`は実装済み（[game_manager.gd:477](autoload/game_manager.gd#L477)）だが、`pomodoro_config.tres`の宝箱4種すべてで未設定。**現状ゼロ** |
| **ショップで買う** | ⬜ **装備が1つも並んでいない。** 検証用の0Gスロットを消した結果 |

**つまり装備を手に入れる方法は作業場だけ。** 最短で木の剣（建築20・30分）。

### 2-5. 鍛冶（等級） ✅

- **場所は装備画面**（作業場ではない）。待ち時間なし・失敗しない・素材だけ
- **上限は等級3**（`MAX_EQUIPMENT_GRADE = 3`）
- **コスト**：等級 g から g+1 へ上げるのに `forging_material_1` を **4×(g+1)** 個
  - 1→2 で **8個**、2→3 で **12個**、**1個を等級3にするのに合計20個**、5部位なら**100個**
- **効果は加算**：`基礎値 + floor(基礎値 × 0.25 × (等級-1))`
  - 等級3で**1.5倍**、（上限が10なら）等級10で**3.25倍**

**根拠**：[game_manager.gd:1356-1367](autoload/game_manager.gd#L1356-L1367)（コスト）、[game_manager.gd:1184](autoload/game_manager.gd#L1184)（効果）、[game_manager.gd:1383-1420](autoload/game_manager.gd#L1383-L1420)（実行）

#### 素材に戻す（倉庫の「素材にする」）

- 戻り量＝**基礎3 ＋ 等級を上げるのに払った全額**。等級3なら **3+8+12 = 23個**
- **装備中は不可**
- **場所は倉庫画面**（`warehouse_screen.gd:145`）。鍛冶は装備画面、素材化は倉庫、と分かれている

### 2-6. 枠に刺すもの（宝石・ルーン） 🟡

- `parts: [null, null]` は個体が必ず持つ（長さ固定・`null`込み）
- 枠が開く条件は`PART_SLOT_GRADES = [5, 10]`。`get_open_part_slot_count(grade)`が毎回計算する（状態に持たない）
- **刺せるものは1つも実装されていない**

> **等級の上限が3で、枠が開くのが等級5から。** つまり**いまのデータでは枠は永久に0個**。`get_open_part_slot_count()`は常に0を返す。

## 3. ステータスがどう合成されるか

**保存されているのはレベル由来の素の値だけ。** 研究と装備の補正は保存せず、都度合成する。

```
get_effective_stats(character_id)
  = character_growth.stats            （レベルから _recalc_stats() で計算した素の値）
  + 研究の stat_boost_all の "all"     （現在は res_stat_1 の +3）
  + 装備5部位の合計                    （equip_stats × 等級係数）
```

**根拠**：[game_manager.gd:904-919](autoload/game_manager.gd#L904-L919)

**これを呼んでいるのは育成画面・装備画面・戦闘の3箇所。** 戦闘（`battle_controller.gd`）が生の`stats`を直接読んでいた事故があり、装備のタスクで修正済み。

### 軸は4本

`_stat_keys()`は `hp` / `atk` / `def` / `spd` の4本（[game_manager.gd:998-1004](autoload/game_manager.gd#L998-L1004)）。**9軸は1本も入っていない。**

### いまの式で到達できる上限（参考値）

等級3・全部位最良・Lv30・研究全解放の剣士：

| | 素の値(Lv30) | 研究 | 装備(等級3) | 合計 |
|---|---|---|---|---|
| hp | 352 | +3 | +97 | **452** |
| atk | 76 | +3 | +22 | **101** |
| def | 35 | +3 | +26 | **64** |
| spd | 89 | +3 | +3 | **95** |

（仮に上限を10に伸ばした場合の装備ぶんは hp+210 / atk+48 / def+58 / spd+6。**`def`が現在の2.7倍になる。** 9軸で`def`を除算にするとき、この幅が効いてくる）

## 4. セーブに何が入るか

育成ループに関係する部分だけ。

| キー | 中身 | 備考 |
|---|---|---|
| `character_growth.<char_id>.level` | int | |
| `character_growth.<char_id>.stats` | `{hp, atk, def, spd}` | **レベル由来の素の値だけ。** 研究・装備は含まない |
| `character_growth.<char_id>.skills` | `{}` | **常に空。誰も書かない** |
| `character_growth.<char_id>.equipment` | `{head, armor, legs, weapon, accessory}` | 値は`instance_id`（`eq_7`）か`null` |
| `equipment_instances.<eq_N>` | `{item_id, grade, parts}` | **性能値は持たない** |
| `next_equipment_instance_id` | int | |
| `research_tree.<node_id>` | `{unlocked, effect_type, effect_value, prerequisites}` | 起動時にマスターから流し込み、`unlocked`だけ残す |
| `materials` | `{material_id: int}` | |
| `crafting_queue` | `[{queue_id, recipe_id, started_at, duration_sec, ...}]` | キューは1本 |

**育成データは遅延初期化。** エントリが無ければ`characters.json`から既定値を返し、保存はしない（[game_manager.gd:891-896](autoload/game_manager.gd#L891-L896)）。キャラを増やしても移行処理が要らない。

### ロード時の正規化

`_normalize_equipment_from_save()`が3つを直す（[game_manager.gd:2055](autoload/game_manager.gd#L2055)）：

1. `grade`を`int`に戻す（JSON復元で`3.0`になる）
2. `parts`を長さ`PART_SLOT_COUNT`に揃える。**枠を減らしてもあふれた部品を配列から消さない**
3. `equipment`を5部位に揃え、個体IDでない値（第1弾の`item_id`直書き）を`null`に戻す
