## 1. コンセプトと設計原則

**ポモドーロ（作業時間管理）をこなすと報酬がもらえる、拠点育成×簡易戦闘のハイブリッドゲーム。**

**対象プラットフォーム：PCのみ（Steam前提）。**

> PC専用と確定したことで、拠点を「デスクトップコンパニオンのように眺める」方針が成立する。Steam Rich Presenceも自然に乗る。UIもタップ前提の大きなボタンに縛られない。

### 設計原則（迷ったときの判断基準）

- **「ポモドーロをやったらご褒美」という約束を裏切らない**
- **プレイヤーに「やって後悔した」と思わせない**
- **頑張る楽しさを、素直に嬉しい手応えとして返す**

この原則から導かれた具体的な決定：

| 決定 | 原則との対応 |
|---|---|
| 戦闘に負けてもスタミナは全額返る | 失うのは時間だけ。実験のコストがゼロ |
| ポモドーロ報酬は必須の壁にしない | 作業を強制する構造にしない |
| ％系ステータスの上限を超えた分は変換する | 無駄になる強化を作らない |
| 割り振りポイントは無料で振り直せる | 選択ミスで詰まない |
| 等級を上げると必ず何かが開く | 空振りの強化を作らない |

## 2. 全体ループ

```
ポモドーロで作業する
  ├─ 作業時間に応じてスタミナ
  ├─ 加護のしきい値でポモドーロ宝箱（建築素材・レア素材）
  └─ 1日のノルマ達成でノルマトークン

スタミナを使ってステージに挑む
  ├─ シナリオステージ（進行）／周回ステージ（素材）
  ├─ 固定報酬（ゴールド・素材）＋抽選ドロップ（装備・装飾）
  └─ 負けたらスタミナは全額返る

手に入れたものを使う
  ├─ 装備を分解 → 鍛冶素材・装飾素材
  ├─ 鍛冶素材で装備の等級を上げる → スロットが開く
  ├─ 装飾をスロットに刺す（刺すときに出目が振れる）
  ├─ レベルを上げる → 割り振りポイント・スキル・パッシブ
  └─ 研究ボードを進める → レベル上限・各種ボーナス

建築素材で拠点を広げ、作業場を強化する
```

### 資源の蛇口と出口

| 資源 | 入る場所 | 使う場所 |
|---|---|---|
| ゴールド | ステージ固定報酬 | ショップ（日替わり・週替わり・月替わり） |
| 鍛冶素材（4段階） | **装備の分解（等級帯で段階が決まる）**、周回ステージ、ショップ | 装備の等級上げ |
| 装飾素材 | 装飾の分解、**周回ステージ（装飾系統）**、ショップ | 装飾の等級上げ、作業場の装飾製作 |
| 建築素材（**木→石→鉄→金の4段階**） | **シナリオステージ（美味しい）**、ポモドーロ宝箱、ショップ | 拠点の建設・拡張、ギルド施設のレベル上げ、**研究のコスト** |
| 経験値素材 | **シナリオステージ（美味しい）** | キャラのレベルアップ |
| 研究用素材 | 作業場（中間素材として製作） | 研究ボードの解放 |
| スタミナ | ポモドーロ、毎朝4:00のデイリー | ステージ挑戦 |
| レア素材 | ポモドーロ宝箱のみ | ショップの特別枠、**ルーンの入手** |
| ノルマトークン（再掲） | **加護の最終しきい値に到達** | ショップの専用タブ |
| ダンジョン用素材 | ショップ（ゴールドで交換・日替わり／週替わり） | 高等級帯の強化、指定の装飾素材との交換 |

### 素材はすべて4段階で揃える

| 素材 | 段階 |
|---|---|
| 鍛冶素材 | 下級・中級・上級・超級 |
| 建築素材 | 木・石・鉄・金 |
| 装飾素材 | （同様に4段階） |

> **規則が1つで済むので、プレイヤーが覚える量が減る。** 研究と拠点が建築素材を取り合う問題も、「序盤の研究は木、終盤は金」と段階で自然に分かれる。

**上位段階の入手：**

- **シナリオの進行に応じて、上位段階が落ちるようになる**
- **ショップでも買える**
- **作業場での下位→上位変換は行わない**（素材の融通はショップに一本化した）

**等級帯と要求段階の対応も鍛冶・装飾で同じ形にする。**

| | 等級 | 4段階の割り方 |
|---|---|---|
| 装備 | 1〜10 | 10を4分割（刻みは調整） |
| 装飾 | 1〜5 | 5を4分割（装備より細かい） |
| 鍛冶屋トークン | **装飾を刺すたびに貯まる** | 装飾の出目を最高値に確定させる |
| ルーンのかけら | **ルーンが5段階まで育った後の重複分** | 好きなルーンと交換 |

**装備・装飾の「かけら」は廃止した。** 中間概念を作らず、分解で直接素材にする。

**ただしルーンのかけらは別物として存在する**（7-5参照）。ルーンだけは分解方式ではなく重ね強化方式のため、あふれた重複分の受け皿が要る。

**ゴールドは「手数料」として広く薄く使う。** ショップの購入だけでなく、装備の等級上げ・装飾を刺す・研究の解放といった操作それぞれに少額が乗る。どの遊び方をしていてもゴールドが減り続けるので、死に資源にならない。

## 3. 戦闘

### 3-1. 基本構造

- **3人編成。** 味方3人が自動で敵に接近し、間合い内で自動攻撃する
- **リアルタイム＋クールダウン制。** 通常攻撃と移動はオート、プレイヤーはスキル発動だけを行う
- **オート発動への切り替えも可能。条件は「CDが明けたら即撃つ」**

> 単純で予測しやすい。しかも「オートは手動より弱い」が自然に成立するので、手動で撃つ意味が残る。回復を溜めておく、範囲攻撃を敵が集まるまで待つ、といった判断はプレイヤーの領分。
- **1ステージ＝5ウェーブ。** 5ウェーブ目にボスが出る
- **ウェーブ間はHP・バフ・クールダウンを引き継ぐ**（連戦）。位置だけ左端に戻る
- 死亡した味方は復活しない
- 1ステージの想定所要時間は2〜3分（**実際に遊んでから調整する**）

### 3-2. スキル

- **各キャラは6つのスキル候補を持ち、そこから2つを選んで戦闘に持ち込む**
- スキル1は武器スロット、スキル2はアクセサリースロットに対応する（ルーンとの紐づき。7章参照）
- 候補の解放：初期2個 ＋ Lv5・10・15・20 で1個ずつ ＝ 計6個
- チャージスキルの仕様は既存のまま（0秒=50%／ジャスト1.0秒±0.15=130%／ためすぎ=100%）

### 3-3. 敗北時

- **報酬なし。ただしスタミナは全額返る**
- ステージは最初からやり直し
- リトライは勝つまで無料

> 有限スタミナで挑む設計なので、負けてスタミナを失うと編成を試す実験ができなくなる。失うのは時間だけにする。

## 4. ステージ

### 4-1. 構成

| 種類 | 役割 | 解放 |
|---|---|---|
| **シナリオステージ** | 進行の主軸。章→ステージ | 1つ前をクリアで解放 |
| **周回ステージ** | 素材集め専用。**素材系と装飾系に分かれる** | **シナリオの進行度に応じて解放** |

**ステージ帯ごとに出るものが違う。**

| | 美味しいもの |
|---|---|
| シナリオステージ | **建築素材・経験値素材** |
| 周回ステージ（素材系） | 鍛冶素材 |
| 周回ステージ（装飾系） | 装飾素材・装飾 |

> シナリオを進める理由が進行だけでなく資源面にも生まれる。スキップ周回でシナリオを回す動機が「建築素材と経験値」になり、周回ステージは「鍛冶素材と装飾」を取りに行く場所になる。

- **シナリオステージも周回できる**
- **2回目以降はスキップ周回ができる**（戦闘画面を経由せず、スタミナを消費して報酬だけ受け取る）
  - **固定報酬も抽選ドロップも通常通り引く。** 純粋な時短
  - **回数を指定してまとめて実行できる**（スタミナを残す判断ができるよう、全消費の一括ではない）

> スキップ周回があると、遊びたいときは戦闘で、忙しいときは一括消化で、とスタミナの使い分けができる。

### 4-2. 報酬

**固定報酬＋抽選ドロップの二立て。**

| | 中身 |
|---|---|
| 固定 | ゴールド、経験値素材、各種素材 |
| 抽選 | **装備・装飾**（分解方式の主要な供給源） |

- ステージによって落ちるものが違う
### 4-4. 宝箱のドロップテーブル

**入手元ごとに別テーブルを持つ。**

| 入手元 | テーブル | 中身 |
|---|---|---|
| **戦闘** | **シナリオの進行度で切り替わる** | 素材・装飾 |
| **ポモドーロ** | 加護のしきい値ごと | 建築素材、レア素材（11章） |
| **ショップ** | ゴールドで交換 | ダンジョン用素材など |

**宝箱専用のダンジョンは作らない。** ダンジョンで得られるはずだった素材は、ショップの日替わり・週替わり枠でゴールドと交換する形にした。

> 実装コストが高いわりに、結局はドロップテーブルを引くだけの行為になる。面白さに直結しないものは作らない。

### 4-3. スタミナ

- **ステージ挑戦時に固定量を消費**（ステージごとに設定）
- 回復は**ポモドーロ**と**毎朝4:00のデイリー付与**のみ。**時間経過による自然回復は無い**
- 上限は100、ポーションで飲んだぶんは上限を超えてよい（既存仕様のまま）

## 5. キャラクター

### 5-1. 入手

- **シナリオ進行で仲間が増える**
- **DLCで追加キャラ**
- ガチャ・重複・凸の概念は無い。キャラは有限

### 5-2. レベル

- **最大レベル100**
- 上限は研究ボード（戦闘カテゴリ）で段階的に解放していく
- **レベルアップでステータスは自動で上がらない**

**経験値素材のコストは、序盤を安く・上位を重くする。**

> 控えキャラを最低限使える状態にするのは簡単で、主力を上限まで押し上げるのは重い。新しく仲間が入ってもすぐ戦線に出せる。控えキャラを別扱いにする仕組みは作らない。

> 既存実装は`3 + 1.0×(level-1)`の線形（Lv1→10で63個）。**立ち上がりを寝かせて後半を跳ねさせる式に差し替える。** 式は`.tres`に文字列で持ち`Expression`で評価する仕組みが既にあるので、差し替えるだけで済む。

| レベル | 何が起きるか |
|---|---|
| 5レベルごと | **割り振りポイント**を得る |
| 5・10・15・20 | **スキル候補が1つ解放**（初期2個＋4個＝6個） |
| 20レベルごと | **パッシブが1つ解放**（計5個） |

> **序盤は報酬が重なる。** Lv20到達時はポイント・スキル4個目・パッシブ1個目が同時に来る。区切りとして強い山になる。

### 5-3. 割り振りポイント

- **実数軸のみに振れる**（`hp` / `atk` / `mag` / `def` / `mdef`）
- **振れる軸はキャラごとに違う。** `characters.json`に`allocatable_stats`の配列を持たせる
- **％系（`crit_rate` / `crit_dmg` / `atkspd` / `haste`）には振れない**

> ％系に振れると、レベル100まで振り切った時点で紋章（装飾3段階目）が無意味になる。`PLAN_STATS_AND_FORMULAS.md` 4章が`growth_per_level`に％系を入れないと決めたのと同じ理由。

- **いつでも無料で振り直せる**
- **プリセットを保存できる**（5-5参照）

### 5-4. パッシブ

- **1キャラ5個**（Lv20/40/60/80/100）
- レベル帯によって種類が違う

| 帯 | 方向性 |
|---|---|
| 序盤 | スキルを強くする（倍率アップ・CD短縮） |
| 中盤 | 戦闘中の条件発動効果（HP半分以下で…など） |
| 終盤 | 役割を深める効果（前衛なら挙動、回復役なら回復量） |

- ライフスティール・HP自動回復はパッシブの候補として残っている（`PLAN_STATS_AND_FORMULAS.md` 3章）

### 5-5. プリセット

**2階層で持つ。**

```
キャラプリセット（キャラごとに複数）
  ├─ 割り振りポイントの配分
  ├─ スキル選択（2枠）
  ├─ 装備一式
  └─ 移動系ルーンの移動量設定

編成プリセット（3人の組み合わせ）
  └─ 「誰の、どのキャラプリセットを使うか」を参照で持つ
```

- **参照方式。** キャラ側のビルドを直すと、それを参照している全編成に反映される
- 装備は個体なので、同じ個体を2人が同時に装備することはできない

## 6. 装備

### 6-1. 部位と個体

- **5部位**：頭 / 上半身 / 下半身 / 武器 / アクセサリー（内部キー：`head` / `armor` / `legs` / `weapon` / `accessory`）
- **頭・上半身・下半身の3つを「防具」系統として扱う**
- **装備は個体として持つ**（`equipment_instances`。既存実装のまま）
- 同じ装備を複数本持てる。ビルドの切り替えは「付け替え」ではなく「持ち替え」で行う

### 6-2. 等級

- **1〜10の10段階**
- **レアリティ＝等級。** 別軸ではない
- 効果は**加算**：`基礎値 + floor(基礎値 × 0.25 × (等級-1))`

### 6-3. 等級を上げる方法（分解方式）

```
いらない装備を分解する → 鍛冶素材になる
鍛冶素材を払って、育てたい装備の等級を上げる
```

- **9個合成は採用しない。** 等級ごとに9倍になるため、等級10を1個作るのに等級1が9^9＝約3.8億個必要になり、10段階と両立しない
- 鍛冶素材は4段階（下級・中級・上級・超級）。**等級帯ごとに要求する段階が上がる**
- **分解して出る段階も、装備の等級帯で決まる**（例：等級1〜2→下級）。刻みはバランス調整で決める

> **⚠ 等級帯の境界に注意。** 10段階を4分割すると境界が等級5をまたぐ可能性があり、スロット解放の節目と混ざって分かりにくくなる。`HANDOVER_STATS_AND_EQUIPMENT_V2.md`の「対応表をプレイヤーに覚えさせない刻みにする」がここに効く。
- 装飾も同じく分解方式。分解すると装飾素材になる

> **3×3グリッドのUI演出は残してよい。** 中央に強化したい装備、周囲8マスに分解する装備を置くと、分解と強化が一度に走る。儀式感を保ったまま中身は分解方式。

### 6-4. 等級ごとに開くもの

**等級を上げると必ず何かが開く。空振りの等級が1つも無い。**

| 等級 | 開くもの |
|---|---|
| 3 | 宝石枠 1つ目 |
| 4 | 宝石枠 2つ目 |
| **5** | **部位ごとの特別枠**（下記） |
| 6 | 護符枠 1つ目 |
| 7 | 護符枠 2つ目 |
| 8 | 紋章枠 1つ目 |
| 9 | 紋章枠 2つ目 |
| **10** | **部位固有のパッシブ** |

**等級5で開く特別枠は部位によって違う。**

| 部位 | 等級5で開く枠 |
|---|---|
| 武器 | **ルーン枠 ×1**（スキル1に対応） |
| 防具（頭・上半身・下半身） | **ワイルド枠 ×1**（宝石・護符・紋章のどれでも入る） |
| アクセサリー | **ルーン枠 ×2**（スキル2に対応） |

**装備1個の最終的な枠数：** 基本6枠（宝石2・護符2・紋章2）＋ 特別枠1〜2。

### 6-5. 入手経路

- **ステージの抽選ドロップが主力**
- **作業場での装備製作は廃止する**（既存レシピ7件は削除対象）
- ショップの常設ラインナップは未定

## 7. 装飾とルーン

### 7-1. 全体像

**装飾は4種類。** 基本3種（宝石・護符・紋章）＋ ルーン。

| 種類 | 性質 | 入る枠 |
|---|---|---|
| **宝石** | ステータスの実数値（`hp` / `atk` / `mag` / `def` から自由に） | 宝石枠、ワイルド枠 |
| **護符** | 地味なパッシブ（防御・生存系） | 護符枠、ワイルド枠 |
| **紋章** | 特殊ステータス（％系） | 紋章枠、ワイルド枠 |
| **ルーン** | スキル発動時の追加挙動 | ルーン枠のみ |

- **装飾は5等級**
- 等級を上げる方法は装備と同じ（分解方式）

### 7-2. 宝石

- 実数軸（`hp` / `atk` / `mag` / `def` / `mdef`）に自由に対応する
- 汎用枠として広く使える

### 7-3. 護符

**9軸に入れなかった防御・生存系の効果を担当する。**

- `def` / `mdef` / `hp` の底上げ
- **HP自動回復**
- **ウェーブ間の回復**（5ウェーブ連戦向け）
- **回避**（上限20%程度）

> 戦闘中の回復は僧侶の領分を侵すが、ウェーブの合間なら役割が被らず、5ウェーブ突破という目標に直接効く。回避は上限20%なら「たまに得する」に収まる。

### 7-4. 紋章

- ％系ステータス（`crit_rate` / `crit_dmg` / `atkspd` / `haste`）
- 割り振りポイントでは伸ばせない軸なので、ここが唯一の供給源になる

### 7-5. ルーン

- **武器＝スキル1、アクセサリー＝スキル2に紐づく**
- **そのスキルを撃つと発動する。ルーンごとに固有のクールダウンを持つ**
- **発動タイミングはスキルの直前**

**効果の例（今後追加予定）：**

- キャラをジャンプさせる / 前進させる / 後退させる
- シールドを張る
- バフをかける / 回復する
- 近くの敵にデバフをかける

> **移動系が入ると、オートバトルなのにプレイヤーが位置をコントロールできる瞬間が生まれる。** 後退で敵の攻撃を回避する、前進で射程に入れる、といった判断がスキル発動のタイミングに乗る。

> **スキルの直前に発動する理由：** 前進してから攻撃すれば当たる、シールドを張ってから踏み込める。順序が逆だと意味が消えるものが多い。

**⚠ 実装上の注意：** `battle_controller.gd`は毎フレーム最も近い敵に接近する処理を持っている。**後退させても即座に前進し直す。** ルーンによる移動中は自動移動を止める等の制御が要る。**具体的な振る舞いは実装時に触ってから決める**（12章の未決事項）。

### 7-6. ランダムロール

- **振れるのは効果量の大小のみ**（種類は振れない）
- **刺すときに振れる**

| | |
|---|---|
| インベントリ上 | 種類と等級だけを持つ**スタック品**。個体データを持たない |
| 刺した後 | `parts`に`{装飾ID, 等級, 出目}`として個体化する |

- **外すと装飾は壊れる**（分解素材になる）
- ビルドの切り替えは装備を複数持って刺し分けることで行う
- **鍛冶屋トークンを使うと、刺すときの出目を最高値に確定できる**
- **鍛冶屋トークンは装飾を刺すたびに貯まる**

> 刺せば刺すほど確定に近づく。外れロールを引いた回数がそのまま次の確定に変わるので、運の悪さが蓄積して報われる。天井として機能する。

### 7-7. ルーンだけは別系統

**ルーンにはランダムロールが無い。**

| | 宝石・護符・紋章 | ルーン |
|---|---|---|
| 強化方法 | 分解方式（等級1〜5） | **同じものを重ねる（5段階まで）** |
| 段階が上がると | 効果量が増える | **効果量が増える。移動系は移動量の選択肢が増える** |
| ロール | 刺すときに効果量が振れる | **無し** |
| 重複したら | 分解して装飾素材に | **5段階を超えた分はルーンのかけらになる** |
| かけらの使い道 | — | **好きなルーンと交換できる** |

> ルーンの効果は挙動そのものなので、量が振れるロールと相性が悪い。重ね強化のほうが筋が通る。かけら交換があるので、被り続けても損をしない。

**移動系ルーンの移動量は事前に設定する。**

- **戦闘中に選ぶのではなく、ビルドの一部として固定する**
- 5段階まで育てると「少し下がる」から「大きく引く」まで選べるようになる
- **設定はキャラプリセットに含める**。ステージごとの使い分けはプリセット切り替え1回で済む

> 戦闘中の操作を増やさない。プレイヤーがやることはスキル発動だけという原則を保ったまま、準備の段階で判断が生まれる。

**入手経路：ポモドーロ報酬のレアな枠。**

> ルーンは戦闘の挙動そのものを変える要素で、ステータスの数値より体験への影響が大きい。それが作業をこなした人にだけ届くなら、「ポモドーロをやると戦い方が変わる」という因果になる。

## 8. ステータスと計算式

**`PLAN_STATS_AND_FORMULAS.md`が土台。** ただし軸が9→10本に増え、上限の持ち方を詰めた。

### 8-1. 10軸＋固定の`spd`

**`PLAN_STATS_AND_FORMULAS.md`は9軸だったが、魔法防御を足して10軸になった。**

| キー | 種類 | 計算 | 上限 |
|---|---|---|---|
| `hp` | 実数 | 加算 | 不要 |
| `atk` | 実数 | 加算 | 不要 |
| `mag`（魔力） | 実数 | 加算 | 不要 |
| `def`（物理防御） | 実数 | 除算 | 不要 |
| **`mdef`（魔法防御）** | 実数 | 除算（`def`と同じ式） | 不要 |
| `atkspd`（攻撃速度） | ％ | 除算 | **秒数の下限で持つ** |
| `haste`（CD短縮） | ％ | 除算 | **100%** |
| `crit_rate` | ％ | 抽選 | **100%** |
| `crit_dmg` | ％ | 倍率 | 不要 |
| `spd`（移動速度） | 実数 | そのまま | **固定。動かさない** |

> **`mdef`を足した理由：** `def`だけだと物理も魔法も1軸で対処できてしまい、護符が単調になる。2軸あると「物理相手か魔法相手か」で選ぶ護符が変わる。

> **`PLAN_STATS_AND_FORMULAS.md`が属性防御を落とした理由（「ステージごとに正解の装備が変わると、組み替えが苦痛になる」）は、`def`/`mdef`の2軸には当てはまらない。** プリセットが2階層で入り、パーティ選択画面で切り替えられるようになったため、装備を組み替えずに別ビルドで対応できる。

**敵にも`mag`を持たせ、魔法を使う敵を用意する。** `mdef`が最初から機能し、敵の差別化（物理型／魔法型）にもなる。

### 8-2. 式

```
攻撃間隔        = base_attack_interval_sec / (1 + atkspd / 100)
クールダウン    = base_cooldown_sec        / (1 + haste  / 100)
物理の被ダメージ = damage × 100 / (100 + def)
魔法の被ダメージ = damage × 100 / (100 + mdef)
```

- **`crit_rate`が100%を超えた分は`crit_dmg`に変換する**（無駄になる強化を作らない）
- **`get_effective_stats()`は生の合計を返す。上限は使う瞬間に掛ける**（育成画面で「上限に当たっている」ことが見えるように）

### 8-2-1. 防御の除算式について（なぜ上限が要らないか）

**実効HPで見ると完全に線形。**

| `def` | 被ダメージ | 実効HP |
|---|---|---|
| 0 | 100% | 1.0倍 |
| 100 | 50% | 2.0倍 |
| 200 | 33% | 3.0倍 |
| 300 | 25% | 4.0倍 |

**`def` 1ポイントが常に実効HP+1%。** 最初から最後まで価値が変わらないので、上限が要らず、終盤に死に軸にもならない。

> 逓減するのは「被ダメージ削減率」であって、生存力は逓減しない。減算式（`atk - def`）にすると、敵の攻撃力8〜12に対して`def`を12積んだ瞬間に無敵になり、装備を作る前に壊れる。

### 8-2-2. ％系の上限の持ち方

**`atkspd`は「秒数の下限」で持つ。％の上限ではない。**

％で上限を置くと、キャラごとに壊れ方が違う。攻撃間隔2.0秒のキャラが100%で1.0秒になるのは問題ないが、0.6秒のキャラは0.3秒になって当たり判定とアニメーションが破綻する。**上限を％で揃えると、遅いキャラは損をして速いキャラは壊れる。**

`min_attack_interval_sec`を1本置けば、どのキャラでも同じ物理的制約として働く。育成画面に「0.35秒（下限0.4秒）」と出せる。

**`haste`は100%を上限とする（仮）。**

- 最短でも元のCDの半分まで
- **⚠ 実装時の制約：チャージスキルはジャストが1.0秒。元のCDを2.0秒以上にしておかないと、チャージし終わる前に次が撃てる状態になり意味が壊れる**
- **⚠ ルーンはスキル発動時に固有CDで発動する。スキルCDがルーンCDより短いと、ルーンが発動しない空撃ちが増える**

> スキルはこのゲームで唯一の手動入力なので、CDが短くなるほど押しっぱなしに近づく。式は破綻しないが、体験と他システムとの衝突が起きる。

**％系の上限はすべて100で揃う**（`haste` / `crit_rate`）。プレイヤーが覚える数字は1つで済む。`atkspd`だけは秒数で持つ。

### 8-3. ステータスの供給源

```
最終ステータス
  = キャラの基礎値（レベルでは変わらない）
  + 割り振りポイント（実数軸のみ・キャラごとに振れる軸が違う）
  + 装備5部位の合計（equip_stats × 等級係数）
  + 装備の全体ボーナス（下記）
  + 装飾（宝石・護符・紋章）
  + 研究のバフ
```

### 8-4. 全体ボーナス

- **装備の最大等級が上がると、装備全体の性能が上がる**
- **加算。乗算にしない**

> 乗算にすると「装備強化 × 全体ボーナス」が二重にかかり、等級が上がるほど伸びが指数的に跳ねる。序盤は何も感じないのに終盤で数値が破綻する。

- **装飾は全体ボーナスの対象外**（種類が多く、集める体験も強化ペースも装備と違うため）
- 研究のバフは別バケットとして扱う

## 9. ギルド

### 9-1. 研究

**カテゴリごとに分かれた一本道のボードを、複数回クリアしていく。**

- ツリー状の分岐は作らない（長くなりすぎるため）
- **1周クリアすると、内容の違う次のボードに切り替わる**
- **ボードの中間と最後に、区切りとして大きめのバフ**（マイルストーン）
- 実装上はノードの配列。中間ノードとボスノードにフラグを持たせるだけで済む

**カテゴリ：**

| カテゴリ | 内容 |
|---|---|
| **戦闘** | **レベル上限の解放**（100まで段階的に）、ステータスバフ |
| **作業場** | 製作時間の短縮、キュー本数、変換レート |
| **宝箱** | ドロップ率、抽選回数、高等級の確率 |

> レベル上限を戦闘カテゴリに集約することで、「強くなりたければ戦闘ボードを進める」という一本の道ができる。

- **コストはゴールドと各種資源。建築素材も使う**

> 研究はいろいろな素材を要求する。素材の出口が一箇所に集中しないので健全。ただし拠点と建築素材を取り合うため、**建築素材が4種類（木・石・鉄・金）に分かれていることを利用して、ノードごとに要求する種類を変えて競合を分散させる。**

### 9-2. ショップ

**4タブ構成。通貨とタブが1対1で対応する。**

| タブ | 通貨 | 中身 |
|---|---|---|
| 日替わり | ゴールド | 素材など |
| 週替わり | ゴールド | 素材など |
| 月替わり | ゴールド | **高等級の鍛冶素材・装飾素材（量ではなく質）、拠点の施設・家具** |
| **ノルマトークン** | ノルマトークン | 特別枠。**レア素材でしか買えないものもここに並べる** |

- 更新周期が違うだけで仕組みは共通。テーブルを3つ（＋トークン用）持てば実装できる
- リフレッシュは毎朝4:00（`GameDate`基準）

### 9-3. 作業場

**「鍛冶＋生産」の総称カテゴリ。**

| 中身 | デモ範囲 |
|---|---|
| 中間素材の製作（研究に使う素材など） | ✅ |
| **装飾のランダム製作** | ✅ |
| **掘削**（下記） | ❌ 後回し |
| 素材の変換 | ❌ **廃止。ショップに一本化** |
| 装備の製作 | ❌ **廃止** |
| 拠点の家具作成 | ❌ 後回し |

> **既存レシピ14件のうち、変換系と装備製作はほぼ全部が削除対象になる。** 作業場は作り直しに近い。ただし役割は明確になった。**時間を払って手に入るのは「作らないと手に入らないもの」だけ。**

**装飾のランダム製作：**

- **種類も等級も両方ランダム**（完全なくじ）
- 投入する素材の質でテーブルが変わる（良い素材を入れると高等級が出やすい）
- 分解で余った素材の出口として気軽に回せる

- 建築素材で作業場自体をアップグレードできる

### 9-3-1. 掘削（デモ範囲外）

**穴を掘り、深さに応じてトークンが手に入る。トークンで家具などと交換する。**

- **消費するのは時間**（既存の`crafting_queue`と同じ形。開始時刻を記録して経過時間で深さが伸びる）
- **深さという単一の軸しかない。** 初心者は浅いところで家具を1つもらえ、上級者は深く潜り続けられる
- **トークン交換なので「掘ったのに要らないものが出た」が起きない**

> **作業場を「戦闘以外のインクリメンタル要素」にするという当初の目的に戻る仕組み。** 深さは数字が伸び続けるので、戦闘とは別の伸び方をする軸になる。

**実装は安い。** `recipes.json`をなぞって深さごとの所要時間とトークン量を書き、画面は残り時間と受け取りボタンだけ。抽選テーブルもドロップ演出も要らない。

**デモで作らない理由は実装コストではなく、家具のグラフィックが無いこと。** 交換先が空だと「掘る意味がない機能」になる。`PROJECT_STATUS.md`の「コスメティックはSDキャラの素材が無いので作れない」と同じ制約。

### 9-4. 倉庫

- インベントリ、図鑑、宝箱の受け取り（既存実装のまま）
- 装備・装飾の分解を行う場所

**⚠ 装飾を刺すのは装備画面。** 着脱・鍛冶に続く3つ目の機能になる。

`HANDOVER_STATS_AND_EQUIPMENT_V2.md`は「装備画面に3つ抱えさせない」と警告していたが、装備の個体を触る操作が1箇所に集まる利点を取った。素材化だけ倉庫にあるのが既に分かれていて不便なため、これ以上散らすほうが悪い。

**装備画面が抱えることになるもの：** 着脱、鍛冶（等級上げ）、装飾を刺す、装飾を外す（壊れる確認）、出目の表示、鍛冶屋トークンの使用判断。**1画面としてはかなり重い。実装時に破綻しそうなら、個体を選んだあとのサブ画面に切り出す。**

## 9-5. 機能の解放順

**シナリオの章で段階的に開く。** 基準は**「戦闘に直結しているものほど早く」**。

```
戦闘 → 装備 → 育成 → ポモドーロ → 装飾 → 研究 → ショップ → 拠点 → 作業場 → ルーン
```

| 順 | 機能 | なぜここか |
|---|---|---|
| 1 | 戦闘 | まず遊びの核を見せる |
| 2 | 装備 | 拾ったものがすぐ強さになる |
| 3 | 育成 | レベル・スキル選択 |
| 4 | **ポモドーロ** | **面白いと分かった後に出す** |
| 5 | 装飾 | 装備の等級3から刺せるので流れが自然 |
| 6 | 研究 | 育成の延長（レベル上限） |
| 7 | ショップ | 資源の融通。戦闘から一段離れる |
| 8 | 拠点 | 眺める楽しみ・建設 |
| 9 | 作業場 | 戦闘に直接効かない |
| 10 | ルーン | 効果が強力。遊びに慣れてから |

> **ポモドーロを最初に出さない理由：** 先に出すと「作業しないと遊べないゲーム」に見える。まず戦って、装備を拾って、育てて、面白いと分かった後で「これを続けるにはスタミナが要る」と繋がる。**順番が逆だと、ゲームが作業の口実に見える。**

**実装：** セーブに`unlocked_screens`が既にあるので、`scenario_chapter`と紐づける。

## 9-6. 詰みの回避

**シナリオが勝てなくなっても、行き止まりにはならない。**

- **クリア済みのシナリオステージを周回できる**
- 研究とレベルで底上げする

**旧ステージの報酬は固定のまま。** 進行度に応じて上がったりはしない。

> 「進めば効率が上がる」が常に成立する。周回は保険であって最適解ではない、という位置づけ。プレイヤーは常に前へ進む動機を持ち続ける。

> スタミナが有限なので、1日にできることをやり切ったら明日に回す、というリズムになる。インクリメンタルゲームとしては、その足踏み期間が「積み上げている実感」になる。

## 10. 拠点

**見て楽しむものであり、各機能へのハブ。**

- **デスクトップコンパニオンのように、眺めて楽しめるものにする**
- 施設ごとに機能があり、ギルド各機能への入り口になる
- **建築素材で、拠点に建てるエリアと作業場のアップグレードを行う**

**建てるもの：**

| 種類 | 例 |
|---|---|
| ギルド各機能の建物 | 研究所・工房・店・倉庫（機能への入り口になる） |
| キャラが過ごす建物 | 宿舎・酒場など |
| 飾り・景観 | 樹木・道・噴水 |
- キャラクターが施設周りを歩き回る（SDキャラ）

**性能への直接の影響は持たせない。**

**資源の自動生産（放置要素）は構想にあるが、デモ版では実装しない。**

> ポモドーロ中に画面の隅で拠点が動いていて、作業が終わるとキャラが増えたり施設が建ったりする。タイマーとゲームが独立していても、拠点だけは作業のお供として存在し続ける。

## 11. ポモドーロとの接続

### 11-1. 独立している

- **タイマーとゲームは完全に別**
- タイマー中もゲームは自由に遊べる。集中を強制しない
- タイマー完了が報酬の発生イベントになるだけ

### 11-2. 報酬

| 報酬 | 条件 |
|---|---|
| **スタミナ** | 作業時間に応じて |
| **ポモドーロ宝箱** | 加護のしきい値到達 |
| **ノルマトークン** | 1日のノルマ達成 |

### 11-3. ポモドーロ宝箱の中身

- **全種類の素材からランダムに出る**
- **戦闘では出ないレア素材**（ルーンの入手源）

> **ポモドーロの価値はスタミナが握っている。** スタミナがなければ何も遊べない以上、ポモドーロは既に全プレイの入り口を持っている。宝箱の中身で差別化する必要はなく、素材はおまけで十分。

> **むしろ宝箱に固有価値を持たせすぎると本末転倒になる。** 「レア素材のためにポモドーロをやる」ではなく、「ポモドーロをやったら臨時収入があった」に留める。

> ランダムなので、特定の素材が枯れたときの救済としても働く。

**レア素材の使い道はショップの特別枠と、ルーンの入手。** 必須ではないが、あったら嬉しいもの。

> ポモドーロ報酬を必須の壁にすると、作業を強制する構造になり「やって後悔しない」から遠ざかる。寄り道の贅沢として機能させる。

### 11-4. ノルマトークン

- **1日のノルマ達成＝加護（ライト／ミドル／ハード）の最終しきい値に到達すること**
- **加護の種類に関係なく、もらえる量は同じ**

> 自分で難易度を選んだ上での達成なので、無理な日はライトを選べば届く。「今日は無理そうだからライト」を選んだ日も報われる量は同じで、努力の差は宝箱の数で回収される。トークンは「続けたこと」だけを測る指標になる。
- **ショップの専用タブで、良いアイテムと交換できる**
- 月に何回か交換できる程度の量に抑える

> 「今日やった」がゲーム内の最上位報酬に直結する。ポモドーロをやる理由が経済に組み込まれる。

### トレーニングモード

**デモに入れる。デバッグ用途を兼ねるため、作る価値が二重にある。**

- `battle_debug_panel.gd`の`_format_unit()`が既にHP・ATK・DEF・ターゲット・攻撃タイマーを毎フレーム出しているので流用が効く
- 速度1〜8倍もDPS計測に使える
- **足りないのは累計ダメージの記録だけ**

> 10軸になると計算式が複雑になるので、DPSを実測できる場所があると調整時に効く。

### 物語の見せ方

**拠点から行ける「物語を読む」画面（任意）。**

- ステージクリア時に自動で流れるのではなく、読みたい人が見に行く
- **作業の合間に遊ぶゲームなので、物語で足止めしない**
- 拠点にシナリオへの遷移ボタンは実装済み。遷移先を作るだけ
- **デモ時点では章のリストが並んでいて中身が空、または「準備中」で成立する**

> シナリオは機能の解放条件でもあり、周回ステージの解放条件でもあり、進行の主軸でもある。**テキストが無くても、ステージクリアで章は進む。**

### 設定画面

**実装しながら決める。** 先に項目を決め切っても、実装中に必要なものが出てくる。

### 入れない

- 拠点の資源自動生産（放置要素）
- 家具の作成、掘削
- イベント交換所、DLCショップ、ダンジョン、戦闘プレビュー画面、ボス画面
- タイマー装飾のマルチプレイ共有

### パーティ選択画面でできること

- **プリセットの選択**
- **メンバーの差し替え**
- **スキル選択・ポイント割り振りの変更**
- **装備の変更はできない**（ギルドで行う）

> 負けてもスタミナが全額返るので、「負ける → その場でスキルを組み替える → 再挑戦」が一つの画面で完結する。装備だけギルドに残すのは、装飾が壊れる仕様があるため事故を減らす目的。
