## 実装の体制（この会話で確定）

### 三段構え

```
【A】計画を書かせる → PRE_PLAN_◯◯.md
【B】人間が確認し、PRE_PLANの末尾に「人間による決定事項」章を追記
【C】実装させる
【D】検証 + IMPL_LOG_◯◯.md 生成
【E】人間がIMPL_LOGをレビューし、必要なら差し戻し
```

**人間の決定事項は必ずPRE_PLANの末尾にファイルとして書き込む。** モデルを分けたり会話が変わったりすると決定が届かないため。その章は本文と矛盾する場合に優先されることを明記する。

### 使うモデル：MiniMax（計画・実装とも）

3モデルを比較した結果。

| モデル | 特徴 | 判定 |
|---|---|---|
| **MiniMax** | 迷った点を隠さず書く。**実機で動かして検証し、できなかった部分だけ正直に申告する。** 自分が壊した箇所も報告してくる | **採用** |
| Gemini | 難しい問題は解けるが、**実際には動かしていない項目に「検証済み」と書く。** 完了条件を勝手に作り直して検証しにくい項目を落とす | 不採用 |
| GPT Luna | 未検証を正直に空欄で返すのは良いが、**実機検証を丸ごと省く** | 保留 |

**採用理由はコストではなく正直さ。** IMPL_LOGの「検証済み」を疑わなくて済むことの価値が大きい。Geminiは差し戻しが2回発生して結局高くついた。

**MiniMaxの弱点は「同じ内容を2回書く」こと。** 計画時も実装時も起きた。対策は下記のツール制約を参照。

### 実測コスト

| タスク | 計画 | 実装 | 備考 |
|---|---|---|---|
| 拠点画面 | $0.13 (MiniMax) | $0.25 + $0.13 (Gemini) | 差し戻し1回 |

## AIに触らせないもの（この会話で確定）

過去に実際に壊れた箇所。**以下は人間がGodotエディタで編集する。**

| 対象 | 理由 |
|---|---|
| **`.tres` ファイル全般** | AIが「値を入れた」と報告して空のままだった事故。Inspectorで人間が入力する |
| **既存ファイルの途中の書き換え** | `_empty_state_template()`への1行追加など。末尾追記しか安全にできない |
| **`state_keys.gd`などの定数ファイル** | 既存定数が消えて全画面が起動不能になった事故。追記のみ許可 |
| **実機での動作確認** | どのモデルも完全にはやらない。人間の担当と割り切る |
| **レイアウト調整** | ラベル位置・余白・フォントサイズ。指示書を書くより自分で触るほうが速い |

EXECを書くときは、これらを「人間が対応済み」として実装スコープから外す。

## AIのツール制約（EXECの§0に毎回書くこと）

| 禁止 | 理由 |
|---|---|
| `edit_file` | このプロジェクトでは動作しない |
| `create_file`に長文 | トークン上限で失敗する。150行超は`cat >>`で分割 |
| `cat >`での上書き | 既存の内容が消える |
| `sed` / `awk` | シェル依存で動作が保証されない |
| 補助スクリプト（`.py`等）の作成 | 誤字修正のために作り始めて止まらなくなる |
| 書き終わったあとの読み返し・誤字修正 | 同上。誤字は人間が直す |

**例外**：既存ファイルに追記した直後だけ`read`で開き、編集前の内容が残っていること・重複行がないことを確認させる。これは誤字チェックではなく破壊チェックなので必ずやらせる。

**追記の前に`grep`で重複を確認させること。** 「同じ内容を2回書くな」と指示しても、本人は1回のつもりなので効かない。書く前の確認を手順に入れる。

### 決定済み

| 論点 | 決定内容 |
|---|---|
| 「1日」の区切り | **毎朝4:00。** 判定は`scripts/utils/game_date.gd`（`GameDate`）に集約。加護選択・ストリーク・ショップのリフレッシュで共用 |
| **加護の効果** | **報酬倍率を廃止し、宝箱スケジュールに変更。** 加護ごとに「累計作業◯分で宝箱1個」。しきい値はその日の累計（1セッションではない） |
| 加護のしきい値 | ライト45分／ミドル45・90分／ハード45・90・135・180分 |

| **ポモドーロ報酬** | **スタミナポーション（作業25分で1個・加護によらず一律）。** gold・素材は0。スタミナは「遊べる時間」に直結するため加護で差をつけない。端数は次回へ持ち越す |
