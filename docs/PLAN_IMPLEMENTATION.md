# 実装計画：新設計をどの順番で作るか

**このファイルは「順番」と「依存関係」だけを持つ。** 何を作るかは`GAME_DESIGN.md`。実装の手順は各`EXEC`。

**`PLAN_CHARACTER_GROWTH_LOOP.md`と`HANDOVER_STATS_AND_EQUIPMENT_V2.md`はこのファイルで置き換わった。** 両方とも冒頭に「破棄」と書くこと。

**決定内容をこのファイルにコピーしないこと。** `GAME_DESIGN.md`の該当章を指す。同じ内容が2箇所にあると、修正時にどちらが正か分からなくなる。

## 1. セーブ構造を触る回をどう分けるか

**これがこの計画の核。**

### セーブに触る変更の一覧

| 変更 | セーブのどこ |
|---|---|
| 10軸 | `character_growth.<id>.stats`にキーが6つ増える |
| 割り振りポイント | `character_growth`に新フィールド |
| パッシブの解放状態 | 同上 |
| スキル選択 | `character_growth.skills`（**現在`{}`のまま**） |
| 等級10 | `equipment_instances.<id>.grade`の値域が広がる（**構造は変わらない**） |
| `parts`の可変長・種類つき | `equipment_instances.<id>.parts`の**要素の型が変わる** |
| 装飾のインベントリ | 新しい入れ物 |
| プリセット2階層 | 新しい入れ物 |
| 新しい素材・トークン | `materials`にキーが増える（**構造は変わらない**） |

### 分け方の判断

**「キーが増えるだけ」と「型が変わる」を区別する。**

- **キーが増えるだけのもの**（10軸・素材・割り振りポイント・パッシブ・プリセット）は、既存セーブで0埋め・空配列になればよい。**移行処理が要らないので、いつやってもよい**
- **型が変わるもの**（`parts`の要素が`null`から`{装飾ID, 等級, 出目}`のオブジェクトに）だけが本当の破壊的変更

**既存セーブは捨ててよい**（`GAME_DESIGN.md` 14章）。デモ前なので移行処理は書かない。`_normalize_equipment_from_save()`が不正な値を`null`に戻す既存の仕組みで足りる。

- [x] **確定：分ける。** セーブ構造を触る回を1回にまとめない（2026-08-14）

**移行処理が要らないので、まとめる理由が無い。** 「キーが増えるだけ」のものは既存セーブで0埋め・空配列になればよく、「型が変わる」`parts`も既存セーブを捨てる判断が出ている。**まとめる動機は移行処理の重複を避けることだったが、そもそも移行処理を書かない。**

> **装備の第2弾は「ステータス9軸と同じ会話でやる予定が、装備だけで終わった」前例がある。** 大きくまとめるほうがリスクが高い。

**ただし各回で必ず確認すること：**

- [ ] 新しいキーが無い既存セーブで、`push_error`ではなく**0埋め・空配列**になる
- [ ] ロード時に`_recalc_stats()`を通る経路がある

## 2. 依存関係

**順番を決める前に、何が何を待つのかを確定させる。**

```
10軸 ──┬─→ 装備の equip_stats を10軸に
        ├─→ 敵データに mag / mdef
        ├─→ 装飾の効果（宝石・紋章が軸を参照する）
        └─→ 割り振りポイント（振れる軸が要る）

レベルの役割転換 ──┬─→ スキル選択（Lv5/10/15/20で候補が開く）
                    └─→ パッシブ

スキル選択 ──→ ルーン（武器＝スキル1、アクセ＝スキル2に紐づく）

等級10 ──→ スロットの種類 ──→ 装飾を刺す ──→ 鍛冶屋トークン
                              └─→ ルーン枠

分解方式 ──→ 素材の供給 ──→ バランス実測
ステージの抽選ドロップ ──┘
```

### ここから出る制約

- **装飾は等級3にならないと刺せない。** 等級10への拡張とスロットの種類が先
- **ルーンはスキル選択が動いていないと紐づけられない。** `select_skill()`は現在空実装で呼び出し元0件
- **バランス実測は、分解とドロップが動いてから。** 素材の供給経路そのものが変わった
- **敵の`mag`/`mdef`は10軸と同時。** 片方だけだと`mdef`が死に軸になる
- **作業場は既存レシピがほぼ全滅する。** 作り直しに近く、他と独立しているので後回しでよい

### なぜアラームが1番か

**演出ではなく機能の欠落。** 音が鳴らないと作業終了に気づけず、振り返り入力の120秒を無音で失う。25分働いたのにノーカウントになるのは「やって後悔した」の最も直接的な形。**他と独立していて小さいので、先に片付ける。**

### なぜ10軸が2番か

**触れる軸が増えないと、装飾も割り振りも設計できない。** `_stat_keys()`に足せば育成・研究・装備の合成が全部追従する構造になっているので、**ここを通せば後続が楽になる。**

### なぜ装飾が6番か

等級10とスロットの種類（4）が入らないと刺す場所が無い。**現状は等級上限3・枠が開くのは等級5なので、枠は永久に0個。**

### 9番（機能の段階解放）だけは、器を早めに入れる

**最後にまとめて入れると、開発中ずっと全機能が開いた状態で進むことになる。** 解放順のバグ（開くべきでない画面に入れる、開くべき画面が開かない）に、いちばん最後まで気づけない。

**`unlocked_screens`と`scenario_chapter`の紐づけだけ早めに入れ、機能が増えるたびに1行ずつ登録する。** 9番に残すのは「章の割り当てを決めて全部埋める」作業だけにする。

## 6. 罠

### `GEMS`が通貨として実装済み

**宝石の内部キーに`gem`を使えない。** `state_keys.gd`の20行目。`part_` / `stone_`などの接頭辞にする。**リリース後に改名できない。**

### `MasterDataLoader`が返す数値は`float`

等級の係数もロール値も**必ず`int()`で包む。** ％系は`int`で持つ（`crit_rate: 25`＝25%）。

### `.tres`は既定値を書き出さない

**実際に効いている数値は`.gd`の`@export`初期値にある。** `adventure_config.tres`などは`script = ExtResource(...)`の1行しか無い。

**この罠で既に1件死んでいる：** `gold_per_focus_minute` / `stamina_per_focus_minute` / `materials_per_focus_minute`が3つとも0。

### 状態にマスターの複製を持たない

個体が持つのは等級と刺さっているもののIDだけ。**枠の数を状態に持たず、`grade`から毎回計算する。**

### 200行を超える既存ファイルは設計役が全文を書く

`game_manager.gd`と`battle_controller.gd`の両方に手を入れる段階がある。**差し替えを渡したら`grep`で当たったことを確認する。**

### 装備画面が重くなる

装飾を刺す機能を足すと、着脱・鍛冶・装飾・出目表示・トークン使用で5つを抱える。**破綻しそうなら個体を選んだあとのサブ画面に切り出す**（`GAME_DESIGN.md` 9-4）。

## 7. デモに入らないもの

**作らない判断をしたものを、間違って作らないための一覧。**

- 拠点の資源自動生産（放置要素）
- 家具の作成、**掘削**（家具のグラフィック待ち）
- 作業場での装備製作、素材の変換（**ショップに一本化**）
- 宝箱専用のダンジョン
- イベント交換所、DLCショップ、戦闘プレビュー画面、ボス画面
- タイマー装飾のマルチプレイ共有
- 物語のテキスト（**画面の器だけ作る**）
