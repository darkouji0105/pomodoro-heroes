## 1. ⚠ 一番の判断：**「結果だけ作る」のではなく、内部で本当に歩かせた**

⚠ **14-b の申し送り2 が「`_roll_floor_chest()` は `move_to_node()` からしか呼ばれない。⚠ 周回でも同じ数の宝箱が出るようにすること」と言っていた。**

⚠ **別経路で「結果だけ組み立てる」と、⚠ 宝箱の出現率・深度補正・1フロア最低1回の保証を**2箇所に書く**ことになる。⚠ どちらかを直し忘れると「周回だけ宝箱が出ない／出すぎる」が無音で起きる。**

⚠ **なので `run_floor_auto()` は `start_floor()` → `move_to_node()` を内部で回す。⚠ 初回とまったく同じ経路を通る。**
⚠ **違うのは「レリックを取らない・休憩しない・買い物しない」だけ**（⚠ **これらは呼ばないだけで自然にそうなる**）。

### 2-1. ⚠ 設計役の決め

- ⚠ **踏破済みのフロアだけ周回できる**（⚠ **初回は歩く＝メモ「初回（未踏破）はマップを実際に歩いて探索する」**）
- ⚠ **ルートはランダムに選ぶ**（⚠ **決め打ちだと毎回同じ層の同じノードを踏み、⚠ 宝箱のレアリティが偏る**）
- ⚠ **断る理由は `get_floor_auto_reject_reason()` の1本**（⚠ **画面で条件を書き直さない。⚠ CLAUDE.md 6番**）
- ⚠ **ショップは無料ガチャだけ自動処理**（⚠ **持ち帰れる資産のため。⚠ 購入とたいまつは発生しない**）
- ⚠ **負ける枝を作らない**（⚠ **踏破済みのフロアなので勝った前提＝メモ「結果だけ受け取る」**）
- ⚠ **1回押して1周。⚠ 「10周まとめて」は作っていない**（⚠ **スタミナ20＝4周が上限なので要らない。⚠ 申し送り**）
