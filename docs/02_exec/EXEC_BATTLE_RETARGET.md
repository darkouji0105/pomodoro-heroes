## 1. いま何がどうなっているか（**実コードで確認済み・2026-08-21**）

`battle_controller.gd:778-785`

```gdscript
func _acquire_target_if_needed(unit: BattleUnit) -> void:
	if not unit.is_alive():
		return
	if unit.target_unit_id != "":
		var t: BattleUnit = _find_unit_by_id(unit.target_unit_id)
		if t != null and t.is_alive():
			return          # ← ⚠ 生きている限り、二度と選び直さない
		unit.target_unit_id = ""
```

⚠ **狙う相手が決まるのは、戦闘開始（と対象の死亡・ウェーブ交代）の1回だけ。**
⚠ **`_reset_party_positions()` が `target_unit_id = ""` を入れているので、ウェーブ交代では選び直す**（`battle_controller.gd:312`）。

⚠ **症状と切り分けの実測は `EXEC_BATTLE_LINEUP.md` §11-5。⚠ 射程の段を入れる前から起きている。**

## 2. ⚠ 事故りやすい箇所

### 2-1. ⚠ 「射程に入ったら固定」は、射程の中に居続ける限り効き続ける

⚠ **一度射程に入れば、より近い敵が来ても乗り換えない**（決定1のとおり）。
⚠ **狙う相手が動いて射程から出た場合は、また乗り換えの対象になる。** ⚠ **これは意図した挙動**（歩いて追う＝まだ攻撃していない）。

### 2-2. ⚠ 通常攻撃の対象は選び直させない（**既存のコメントを守る**）

⚠ **`_fire_basic_attack()` は `target_unit_id` を固定で渡している**（`battle_controller.gd:864-884`）。
⚠ **「対象を選び直さない」と書いてあるのは通常攻撃を撃つ瞬間の話で、⚠ 歩いている間の乗り換えとは別。⚠ この関数は1行も触らない。**

### 2-3. ⚠ 実測値が全部動く

⚠ **停まる `x` が変わるので、段階4〜6の数字が動く。**
→ ⚠ **比較の基準は `EXEC_BATTLE_LINEUP.md` §11-2（`narrow`=3 ／ `wide`=4 ／ `far`=4 ／ `heal`=3）と、⚠ `recast` の `damage` 2 / 8。**

### 2-4. ⚠ 編集したら `grep` で当たったことを確認する

⚠ **`grep -n "attack_range" scenes/adventure/battle_controller.gd` が2件（`_step_unit` と `_acquire_target_if_needed`）になること。**

## 3. 実装（ファイル別）

⚠ **インデントはタブ。**

### 3-1. `scenes/adventure/battle_controller.gd`（**触るのはここだけ**）

`_acquire_target_if_needed()` の早期 return を条件付きにする。

```gdscript
	if unit.target_unit_id != "":
		var t: BattleUnit = _find_unit_by_id(unit.target_unit_id)
		if t != null and t.is_alive():
			# ⚠ 攻撃を始めたら固定（人間の決定・案B）。射程に入るまでは、
			#   より近い相手が居たら乗り換える。
			if absf(t.x - unit.x) <= unit.attack_range:
				return
		else:
			unit.target_unit_id = ""
```

⚠ **`else` に変えること。** ⚠ **元の形（`if ... return` のあとに無条件で `= ""`）のままだと、⚠ 生きている相手を射程外で捨ててしまい、⚠ 下の選抜で同じ相手が選ばれなかったときに1フレーム対象が空になる。**
⚠ **選抜のループ（`:791-801`）は1行も触らない**（決定4）。
