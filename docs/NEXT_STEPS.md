## 3. ⚠ 先に決める必要がある穴（**着手前に人間が判断**）

### 3-1. ⚠ **通常攻撃が `SkillResolver` を通っていない**

```
battle_controller._step_unit()（412〜434行）
  → BattleFormula.roll_crit() → _compute_damage() → target.take_damage() → _pop_damage()
```

⚠ **`SkillResolver._apply_damage()` を通らない。** つまり:

- **ダメージの介入点（`_step_crit_override` / `_step_reduction`）が通常攻撃に効かない**
- **シールドも軽減も反射も、スキルにしか乗らない**

⚠ **PLAN 10-4 は「通常攻撃は『攻撃した』合図を出す」と要求している**が、**式の経路が2本あることは書かれていない。**

**選択肢**：

| 案 | やり方 | 代償 |
|---|---|---|
| **A** | 通常攻撃も `SkillResolver` を通す（内部で1効果のダメージとして解く） | ⚠ **式の経路が1本になる**。ただし `battle_controller` の途中を書き換える（1001行） |
| **B** | 合図だけ出し、介入点は当面スキルだけ | 反射が「スキルにだけ効く」という説明のつかない仕様になる |
| **C** | 今回は合図だけ。介入点の統合は③の回でやる | ⚠ **③で `battle_controller` を触ることになるのを覚悟する** |

### 3-2. 購読の欄の名前と書き場所

`trigger`（自分の実行）と**別の欄にする**ことは PLAN 6-5 / 10章が決めている。⚠ **同じ欄にすると発火経路の一本道が壊れる。** 名前（`on` か `subscribe` か）と、`effects[]` の中に書くのか状態の側に書くのかは未決。

### 3-3. 合図の種類をどこまで作るか

PLAN 10章が挙げているのは**ダメージ・撃破・進入・攻撃**。⚠ **進入（罠）は `host: point` が要り、座標の規則が未決**（`target.range` が18件とも未設定なのと同じ根）。**今回は進入を外すのが自然。**
