## 5. 罠

### ドキュメントの「実装済み」を信じない

**ズレが12回起きている。** ⚠ **段階4では「④-a の完了記録が事実と違っていた」という形で出た**（§0-1）。`grep`で関数の中身を見てから判断する。**勝手に直さず報告する。**

### ⚠ 静的な突き合わせは実機の代わりにならない

⚠ **段階4で、設計役はロード時検証を Python で真似て「OK」と言ったが、実機では10件の赤が出た。** 真似た側にバグが無くても、**本体（`.gd`）にバグがあれば分からない。**
→ ⚠ **静的な確認は「自分のデータが規則に合っているか」までしか言えない。** そう書くこと。

### 関数を足す前に `grep` する

**足す前に `grep -n "func <名前>"`、足したあとにも `grep` で当たったか確認する。**

### ⚠ Windows の bash で `cat >>` すると追記分が CRLF になる

元が LF の JSON に混ざって壊れる。**JSON に追記したら改行コードを確かめる。**

### ⚠ 検証スクリプトの文字コード

⚠ **Windows PowerShell の `Get-Content` は既定が ANSI。** `ja.csv` を読むと**途中までしか読めず**、「キーが無い」と誤判定する。**`[System.IO.File]::ReadAllLines(path, [System.Text.Encoding]::UTF8)` を使うこと。**

### 正常系に警告を付けない・`print` を増やさない

**出したい記録は `BattleLog` へ。** コンソールに流さない。

### インデントはタブ

`.gd`はタブ。**`.json`も既存ファイルはタブ**（⚠ `stages.json` だけトップレベルが半角スペース2つ）。`ja.csv`はUTF-8（BOMなし）。
