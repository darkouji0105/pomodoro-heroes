## 2. このタスクの矛盾を先に把握する（重要）

`PROJECT_STATUS.md`の未確定表に、こう書いてある。

> 敵HP・スキル倍率のバランスは**ステータス9軸と式が入ってから**。`def`が除算になるため、いまの数値は全部意味が変わる

**9軸を入れると、敵HPとスキル倍率の測定値は無効になる。** それを承知でいま測る。理由は2つ。

1. **測り方と記録の型を先に確立する。** 9軸が入ってから初めて測ると、そのときも「測り方が分からない」で止まる
2. **軸の本数に依存しない数値がある。** ゴールド収入・素材収入・ショップ価格・作業場のレート・レベルアップコスト・研究コスト・鍛冶コストは、軸が4本でも9本でも同じ議論になる

| ステージ報酬（ゴールド・素材） | |

**1戦の長さは「測る」が「直さない」。** いまの数字を記録として残し、9軸のときの比較材料にする。

### `.tres`だけ見ても数値は分からない

**`.tres`はGodotが既定値を書き出さない。** `adventure_config.tres`などは`script = ExtResource(...)`の1行しか無い。**実際に効いている数値は`.gd`の`@export`初期値にある。** 必ず両方読むこと。

**この罠で既に1件死んでいる：** `gold_per_focus_minute` / `stamina_per_focus_minute` / `materials_per_focus_minute`が**3つとも0**。`pomodoro_config.gd`で初期値を書かずに宣言され、`.tres`にも書かれていない。**Inspectorを開いても0が並ぶだけで異常に見えない。** ポモドーロの分あたり報酬が死んでいる。**このタスクで直す。**

### コード側にある係数

`game_manager.gd`の`GRADE_STAT_RATIO`（0.25）と`FORGE_COST_PER_GRADE`（4）。**`.tres`へ出すかを判断すること**（出すなら`character_config.tres`と同じ形）。数値管理ルール（`AGENTS.md`）では`.tres`に置くのが正。

## 6. 測ったあとに逆算する

| 直すもの | 根拠にする数字 |
|---|---|
| **ショップの価格** | 1周のゴールド × 何周で1つ買えてほしいか |
| **作業場の交換レート** | 1周の素材量 × 何周ぶんを何時間で交換できるか。**必ず1未満を保つ**（往復で得になると素材が無限に増える） |
| **レベルアップのコスト** | `character_config.tres`の`base_level_up_cost` / `cost_growth_per_level` |
| **研究のコスト** | `research.json`の`cost_amount` |
| **鍛冶のコストと等級4〜10** | `FORGE_COST_PER_GRADE`と`forging_material_1`のドロップ量 |
| **ポモドーロの分あたり報酬** | 0のまま死んでいる3つ（4章） |

**変更は「変更前・変更後・根拠」の3点セットで残す。** 根拠が無い変更は、2日後に自分でも理由が分からなくなる。

### 等級4〜10のコスト表を確定させる

**このタスクの成果物のひとつ。** いま上限は3で、4〜10のコストは未定。

- 等級は**加算**（基礎値の25% ×（等級-1））。等級3で1.5倍、等級10まで伸ばせば3.25倍
- **5部位×等級10まで行った場合の最大値を出しておくこと。** 敵HPを詰めるときの上限の目安になる
- 等級5・10では`parts`の枠が開く（`get_open_part_slot_count()`）。**刺すものはまだ無い**ので、そこに価値を置かないこと
