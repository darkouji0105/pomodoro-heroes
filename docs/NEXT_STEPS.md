## 5. 数値が散っている場所

**8ファイル。まずこの全部を読んで、1つの表にする。**

| ファイル | 何を持っているか |
|---|---|
| `resources/balance/master/stages.json` | ステージ報酬（ゴールド・素材）・敵の構成 |
| `resources/balance/master/enemies.json` | 敵のHP・攻撃・防御・速さ |
| `resources/balance/master/characters.json` | 味方の基礎値・`growth_per_level` |
| `resources/balance/master/items.json` | 装備の`equip_stats` |
| `resources/balance/master/recipes.json` | 作業場の交換レート・所要時間 |
| `resources/balance/master/shop.json` | 価格・在庫 |
| `resources/balance/master/research.json` | 研究のコストと効果 |
| `resources/balance/character_config.tres` | `base_level_up_cost` / `cost_growth_per_level` / 各種formula |
| `resources/balance/pomodoro_config.tres` | 宝箱の中身・スタミナの回復 |

**コード側の係数も1つある。** `game_manager.gd`の`GRADE_STAT_RATIO`（0.25）と`FORGE_COST_PER_GRADE`（4）。**これは`.tres`へ出すかどうかを判断すること**（出すなら`character_config.tres`と同じ形）。

## 6. 何を測るのか

**測っていないものが4つある。全部「1周でいくら入るか」の話。**

| 測るもの | どうやって | いま何になっているか |
|---|---|---|
| **ステージ1周のゴールド** | 3周して平均を取る | 未測定。`shop.json`の価格が全部仮 |
| **ステージ1周の素材**（3種） | 同上 | 未測定。`stages.json`の報酬が仮 |
| **1戦の長さ** | ストップウォッチ。**目標90秒前後** | 味方3人・装備ありで短くなっている可能性 |
| **スタミナの出入り** | ポモドーロ25分で1個、ステージ1回で5消費 | 釣り合っているか未確認 |

測ったら、その数字を基準に**逆算して**直す。

- **ショップの価格** ← 1周のゴールド × 何周で1つ買えてほしいか
- **作業場の交換レート** ← 1周の素材量 × 何周ぶんを何時間で交換できるか。**必ず1未満を保つ**
- **レベルアップのコスト** ← `character_config.tres`
- **研究のコスト** ← `research.json`の`cost_amount`
- **鍛冶のコスト** ← `FORGE_COST_PER_GRADE`と`forging_material_1`のドロップ量

## 7. 装備が入ったことで新しく見る2つ

### 7-1. 研究の全ステータス+3が、戦闘に効き始めている

装備の第1弾で`battle_controller.gd`が`get_effective_stats()`を使うようにした副作用。**それまで研究の`stat_boost_all`は育成画面にしか出ていなかった。**

**既存の数値は「研究が戦闘に効いていない前提」で置かれている。** この分を織り込んで測ること。

### 7-2. 等級で伸びる幅

等級は**加算**（基礎値の25%×(等級-1)）。等級3で1.5倍、等級10まで伸ばせば3.25倍。

**いま上限は3。** 4〜10のコストは未定で、**このタスクで確定させる。** 5部位×等級10まで行った場合の最大値を、作った計算道具で出しておくこと。

## 8. 作るもの（計算道具）

**画面は作らない。** ゲーム内に出すものではなく、数値を決めるための道具。

- 置き場所は`tests/`配下か、リポジトリ外のスクリプト
- **本番コードから参照しない**
- 入力：上記8ファイル
- 出力：
  - レベル1→30に必要な`training_material`の総量と、それが何周ぶんか
  - 研究を全解放するのに必要な`construction_material`と、何周ぶんか
  - 装備を5部位そろえて等級Nにするのに必要な素材と時間
  - 味方3人の合計ステータスの推移（レベル・研究・装備・等級の全部込み）
  - 各ステージの敵の合計HPと、それを削り切るのにかかる秒数の概算

**「何周」と「何時間」の2つで出すこと。** このゲームは待ち時間が資源なので、周回数だけでは判断できない。

## 10. 罠

### 検証用のものを消し忘れる

**これを消さずに測ると、測定値が全部無意味になる。** 4章を最初にやること。

### 測る条件を書き残さない

「1周80ゴールド」だけ残しても、レベルいくつで装備が何だったかが無いと再現できない。**必ず併記する。**

### 途中でコードを直す

バグを見つけても直さない。`PROJECT_STATUS.md`の宿題に書く。**測定の途中で挙動が変わると、何を測っていたのか分からなくなる。**

### 1回で決めようとする

**何日か実際に使う。** 1回の測定で「これでいい」と決めた数値は、たいてい2日目に破綻する。

### `MasterDataLoader`が返す数値は`float`

計算道具側でも`int`と`float`を混ぜないこと。ゲーム側は`int()`で丸めているため、道具側だけ小数で計算すると答えがずれる。
