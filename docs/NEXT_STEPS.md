## 3. このタスクの本体は`BattleUnit`の作り直し

**`scripts/systems/unit.gd`の`BattleUnit`は`hp` / `atk` / `def`しかフィールドを持たない。**

**コンストラクタは既に10個の位置引数**で、6本足すと16個になる。**引数を並べる形のまま増やさないこと。** 呼び出し側（`battle_controller.gd` 157行の味方と255行の敵）で順番を間違えても型が同じなら通ってしまい、実行するまで気づけない。

**構造ごと見直す。** 方針は着手時に決めて合意を取ること（`CLAUDE.md`「大きい変更は先に方針を出して合意を取る」）。候補：

- `stats: Dictionary`を1つ持たせ、`unit.stats[GameStateKeys.STAT_MAG]`で引く
- 名前付きの引数辞書を1つ渡す形にする
- `BattleUnit`に`from_stats()`のような生成関数を足し、`_init()`を呼ぶのはそこだけにする

**どれを選ぶかで`battle_debug_panel.gd`の`_format_unit()`（98〜101行）も直す必要がある。**

## 4. 式は`GAME_DESIGN.md` 8-2が正

### 実装で気をつけること

- **`get_effective_stats()`は生の合計を返す。上限は使う瞬間に掛ける。** 育成画面で「上限に当たっている」ことが見えるようにするため（`PLAN_STATS_AND_FORMULAS.md` 2章）
- **`atkspd`の上限は「秒数の下限」で持つ。％の上限にしない**（`GAME_DESIGN.md` 8-2-2）
- **`crit_dmg`の基礎値は150**（会心で1.5倍）。0にすると会心が「ダメージ0」になる
- **`_percent_stat_keys()`は毎回`Array`を作って`in`で線形探索する。** 毎フレーム呼ぶ場所から呼ばないこと（`_process()`から呼びたくなる）
