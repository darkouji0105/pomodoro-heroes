## このタスクでいま分かっていること

### 使えるもの

| もの | 状態 |
|---|---|
| アイテムIDの台帳 | **`items.json`。** `storage: "inventory"` / `item_type: "equipment"`で1行足せば、倉庫にも作業場にもショップにも乗る |
| レシピ | **`recipes.json`。** `outputs`に装備IDを書けば作業場で作れる。**コード側の変更は不要** |
| ショップ | `shop.json`に`payout_type: "item"` / `item_type: "equipment"`で1スロット足せば売れる |
| `add_to_inventory()` | **本実装済み。** 図鑑の`discovered`も自動で立つ |
| `get_item_count()` / `_consume_item()` / `_grant_item()` | **作業場で追加済み。** `storage`を見て`materials`と`inventory`に振り分ける |
| スロットの状態の形 | `DATA_SCHEMA.md` 3の`character_growth.equipment`。**編集は不要のはず** |
| マスターと状態の同期の型 | **研究・ショップ・作業場で3回書いた`_sync_*_from_master()`** |
| 画面の作り | 1画面・スクロール・行をコードで生成。**ショップと作業場で2回書いた** |

### 決めることになるはず

- **装備の性能データをどこに置くか。** 3案ある。**設計役と相談して決める**
  - `equipment.json`を新設する（`items.json`と2枚に分かれる）
  - `items.json`の各エントリに`properties`として持たせる（台帳が太る）
  - `.tres`に持たせる（**却下でよい**。装備ごとに違う値は`.tres`の単一値で表せない。`ShopConfig`で同じ結論が出ている）
- **スロットの種類と数。** 武器・防具・装飾の3つか、武器1つだけで始めるか。**第1弾は武器1つでいい**
- **装備画面の置き場所。** 育成画面にセクションを足すか、独立した画面にするか
- **どのステータスを上げるか。** `atk`だけで始めるか、4ステータス全部に対応するか
- **`atk_multiplier`をどう扱うか。** `PROJECT_STATUS.md`の未決定表に残ったまま。**加算（`+5`）と乗算（`×1.2`）を両方入れない。** 第1弾は加算だけでいい
- **同じ装備を複数人が装備できるか。** インベントリの`count`と装備状態の整合。**第1弾は「装備したら在庫から減る」が素直**

### スコープの目安

**第1弾は「武器スロット1つ・装備3種・`atk`加算のみ・作業場で作れる」でいい。**

それだけで「作業場で武器を作る → 装備する → 戦闘のダメージが増える」が一周する。

**まず1本通すこと。** 種類・スロット・ステータスを増やすのはそのあと。

### 見た目の注意

**ショップ・作業場と同じ作りにする。** 1画面・スクロール・行をコードで生成・詳細画面なし。

**戻るボタンは1つだけ。** 育成で2つ並んだ件を繰り返さない。

**装備の名前には翻訳キーが要る。** 作業場のレシピ名は`inputs`/`outputs`から組み立てて`ja.csv`を触らずに済ませたが、**装備は`ui_res_<item_id>`が要る**（倉庫画面が`tr("ui_res_" + item_id)`で引いている）。装備を足すたびに`ja.csv`へ1行追記する。

## 作業場で分かった罠（装備でも踏む）

### アイテムの保存先はIDから推測できない

`materials`（`{id: 数値}`）と`inventory`（`{id: {count, type, ...}}`）は構造が違う。**装備は必ず`inventory`側。** `items.json`の`storage`を見て振り分ける`_consume_item()` / `_grant_item()`が既にあるので、それを使う。

### `MasterDataLoader`が返す数値は`float`

装備の性能値も**必ず`int()`で包む。** 包み忘れると`get_effective_stats()`が`atk: 55.0`を返し、セーブにも`.0`が書かれる。

### 状態を変える前に全部の判定を終える

`equip_item()`も「キャラ存在 → アイテム所持 → 装備品かどうか → スロットの妥当性」を全部通してから状態を触る。**装備品でないアイテムを装備できてしまわないこと。**

### マスターの変更を既存セーブに反映する

`items.json`の性能値を変えたら、既存セーブの装備にも反映されるべき。**状態側に性能値をコピーしない。** 装備している`item_id`だけを状態に持ち、性能は`get_effective_stats()`が毎回マスターから引く。

> **育成の`stats`が既にこの形。** レベル由来の素の値だけを保存し、研究の補正は保存せず都度合成している。装備も同じ扱いにすれば整合する。

### 1操作で複数のシグナルが飛ぶ画面は`await`を持たせない

着脱は`character_growth_changed`と`inventory_changed`を続けて発火する。**`remove_child()`してから`queue_free()`する**（`AGENTS.md`「再描画は await を持たせない」）。

### 検証手順は、その出力が実在することを確かめてから書く

育成で「ログで確認する」と書いたが、その`print`に該当項目が無かった。**書く前にコードを見る。**
