## 3. 最初に決めること：スコープ

**「アラーム音を鳴らす」だけでは決まらない。** 音を1つ足すと、その置き場所と再生の仕組みが要る。**どこまでを今回に含めるかを最初に決める。**

| 候補 | 含めるか |
|---|---|
| 作業終了のアラーム音 | **必須**（これが目的） |
| 休憩終了のアラーム音 | 要判断。同じ仕組みで鳴らせる |
| 音を鳴らす共通の仕組み（Autoloadなど） | 要判断。**1音だけなら要らないが、後でSE/BGMが来る** |
| 音量設定・ミュート | 要判断。**設定画面は第2層ごと無い** |
| 戦闘SE・UI SE・BGM | **今回はやらない**（`DEMO_CHECKLIST.md`の音の章） |

**判断の材料：** 音源ファイルが用意できるかは人間しか決められない。**フリー素材を使うのか、作るのかを先に聞くこと。**

## 4. 着手時に確認すること（`grep`で）

**PLANの記述を信じない。ドキュメントと実コードのズレが7回起きている。**

- [ ] **音を扱う仕組みが既にあるか**（`AudioStreamPlayer`・Autoload・`.import`済みの音源）。**無いものとして書き始めない**
- [ ] **作業終了のタイミングがコードのどこか。** タイマー完了 → 振り返り画面への遷移がどう繋がっているか
- [ ] **120秒の猶予をどこで測っているか。** アラームはその開始と同時に鳴る必要がある
- [ ] **バックグラウンド・一時停止中の扱い。** 休憩は自動開始する仕様なので、鳴らす条件が分岐する可能性がある
