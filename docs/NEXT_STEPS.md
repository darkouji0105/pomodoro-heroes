## なぜ育成が次なのか

**素材の使い道がここで生まれる。**

戦闘に勝つと建築素材が手に入るが、いま使う先が一つも無い。倉庫に溜まっていくだけになっている。ポモドーロ→戦闘のループは閉じたが、**その先で何かが強くなる感覚がまだ無い。**

育成が入ると、こうつながる。

```
ポモドーロで働く → スタミナが増える
  → 戦闘に挑む → 素材が手に入る
  → 育成でレベルを上げる → 戦闘が楽になる
  → もっと先のステージに挑める
```

もう1つの理由として、**戦闘側の受け入れ準備が既にできている。** `battle_controller.gd`の味方生成は「育成データがあればそれ、無ければ`characters.json`の基本値」の優先順で書かれているので、**育成画面ができた時点で戦闘側を1行も変えずに反映される。**

## このタスクでいま分かっていること

### 実装済みで使えるもの

| もの | 状態 |
|---|---|
| `GameManager.get_character_growth(id)` | **空の`{}`を返すダミー** |
| `GameManager.level_up_character()` 等 | **`false`を返すダミー** |
| `CHARACTER_GROWTH`の状態構造 | `state_keys.gd`に定数だけある。中身は空 |
| `CharacterConfig`（`character_config.tres`） | `level_up_material_id` / `base_level_up_cost` / `cost_growth_per_level` の3つだけ |
| `characters.json` | 3キャラ分の基本ステータスとスキルIDがある |
| `skills.json` | 6スキル。`user_character_id`で持ち主が書いてある |
| 素材の増減 | `GameManager`の`material_changed`シグナルで通知される |
| モーダル | `Modal.notify` / `Modal.confirm` が使える |

### 決めることになるはず

- レベルアップに必要な素材の種類と数（`character_config.tres`）
- レベルが上がると`hp`/`atk`/`def`/`spd`がどう伸びるか
- スキルスロットの解放条件（研究が無い状態でどうするか）
- 装備をこのタスクに含めるか（**含めないほうがいい。** 装備アイテムがまだ1つも無い）
- 研究によるレベル上限の反映（**研究が無いので、当面は上限なしか固定値**）

### スコープの目安

**第1弾はレベルアップだけでいい。** スキル選択と装備は分ける。

理由は、レベルアップだけで「素材を使う → 戦闘が楽になる」が成立するから。スキル選択は候補が1キャラ2つしかなく、装備はアイテムが存在しない。**検証できないものは作らない。**

## 渡し方で気をつけること（今回から変えた点）

### 完了条件をA章とB章に分ける

EXECの完了条件を2つの章に分けて書く。

- **A章：実装役が確認する項目**。`print`で結果が出るもの（計算結果・状態の変化・JSONの反映）
- **B章：人間が確認する項目**。画面を見る・クリックする・遷移を見るもの

**実装プロンプトで「B章は転記だけして検証しないでください」と明示する。** 黙っていると埋めようとして、原理的にできないことに時間を使う。モーダルのタスクで実際にそれが起きた。

### 200行を超える既存ファイルは設計役が書く

育成画面は新規ファイル中心なので、実装役に向いている。ただし`game_manager.gd`（647行）のダミー関数を本実装に差し替える作業が出るはず。**そこは設計役が全文を書くか、あなたが手で書く。**

- 1つのファイルへの書き込みが2回失敗したら中止して報告
- 1つの症状に対して試す方法は2つまで

## 育成のあとの順番

1. **研究** — レベル上限の解放が育成と直結する
2. **ショップ** — ゴールドの出口
3. **作業場** — 素材の出口。時間投資型
4. **パーティ選択** — 第2層から書く
5. **バランス調整** — ここで初めて実際に何日か使う

**装備・強化・研究が入るまで、本格的な試用はしない。** 数値の調整もそれまで待つ。全部JSONか`.tres`なので後から変えられる。
