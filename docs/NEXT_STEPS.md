## 1. このタスク：**skills.json を割る ＋ 検証用のキャラとスキルを作る**

### なぜこの2つが1タスクなのか

⚠ **デバッグ用スキルを足す仕組みと、キャラごとに割る仕組みは同じもの**（`MasterDataLoader` が複数ファイルを読んでマージする）。**別々にやると同じものを2回作る。**

そして**段階3の後半（購読・条件）が乗ると1スキルが30〜50行になる。** いま18スキルで315行なので、**4人目のキャラで500行を超える。** 割るなら購読が乗る前。

**検証用キャラを一緒に作るのは、段階3の後半で「狙ったスキルを撃つ」手段が要るから。** いまは製品の18スキルしか撃てず、しかも1キャラ2枠しか持ち込めない。

### やること

| # | やること | 誰が |
|---|---|---|
| **1** | **`MasterDataLoader` が skills を複数ファイル読んでマージする**（`_ensure_loaded()` の途中を触る） | ⚠ **設計役**（424行） |
| **2** | **`skills.json` をキャラ別に割る**（`.gd` を触らない・**IDは1つも変えない**） | **実装役に渡してよい** |
| **3** | **`skills_debug.json` と検証用キャラを作る**（`characters.json` に1件・`ja.csv` に7行） | **実装役に渡してよい** |
| **4** | **`training_screen.gd` の `CHARACTER_IDS` に1行足す** | ⚠ **設計役**（const 配列に1行だけ） |

### ⚠ 検証用キャラの入れ方（**先に読むこと**）

**パーティの入れ替え機能は作らない。要らない。**

```
stages.json の party_id → parties.json の members → battle_controller が3体作る
```

**パーティは状態（セーブ）に一切入っていない。** マスターデータから毎回引き直している。だから**`parties.json` の `members` を書き換えてゲームを再起動すれば、それだけで入れ替わる。**

⚠ **`parties.json` を実装役に書き換えさせないこと**（本番データ）。**切り替えは人間が手で1行直す。**

⚠ **ステージを足す道は薦めない。** 解放判定が `stage_order.json` の並び順で「1つ前をクリアしたか」を見ているので、**デバッグステージを先頭に入れると本編の `stage_1` がその後ろに回る。**

### ⚠ 2枠は変わらない（**このタスクでは外さない**）

候補を6個作っても、**同時に持ち込めるのは2つ**。付け替えはギルドのスキル選択画面から。

| やること | 効果 |
|---|---|
| 検証用キャラ1体 × 候補6件 | **6件の中から2つを、ギルドで付け替えて検証できる** |
| 検証用キャラを2〜3体 | `parties.json` の1行を書き換えて再起動 → **別の6件セットに丸ごと入れ替わる** |

⚠ **候補が6件を超えたときにスキル選択画面がどう出るかは見ていない**（スクロールするのか、はみ出すのか）。**まず6件で作り、足りたら増やす。**
